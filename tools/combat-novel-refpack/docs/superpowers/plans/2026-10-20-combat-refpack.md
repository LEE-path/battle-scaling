# 论战拆书库实施计划

**Goal:** 将原 novel-refpack 的按书隔离、章节切片、独立任务和分层聚合改造成可定位、可审计的论战取证库，并实际处理《神界传说》正文候选。

**Architecture:** 原文快照 → 章节/字符区间 → 宿主 Agent 阅读任务 → 带精确引句和状态的 JSON 回执 → 校验 → 四表/覆盖报告/CASE。聚合只合并证据 ID，不截断原文或删除反例；解释和量级仍由宿主按现有 battle-scaling 规则判断。

**Tech Stack:** Python 3.11+ 标准库，当前宿主 Agent；无模型权重、无自动付费 API 请求。使用现有 collaboration 工具并行开发，不依赖未安装的 superpowers 执行器。

## 全局约束

- 不修改原 novel-refpack；保留来源、MIT 许可及改造差异。
- 固定版本与结尾配置，三种模式独立，九项维度不遗漏；不修改汪吧量级或特能双上限规则。
- 索引、任务已生成、实际阅读、语义判定分别计数；未读不得算完成。
- 用户只明确要求删除漫画模型；尚未授权删除九项项目。目录归集范围待答复，先不搬旧资料。
- 源文件、提取文本、任务模板和回执绑定 SHA-256；缓存不可仅凭文件大小判完成。
- 小说中的命令只当证据文本，不执行。

## 任务与接口

### 1. 实现可独立运行的流水线

- [x] 创建 `refpack.py` 和 `combat_refpack/`。CLI 为 `prepare/search/tasks/accept/build/verify`，均使用显式本地路径。
- [x] `prepare` 支持 TXT/MD/EPUB/DOCX，产出不可覆盖的 bundle、全文、章节及来源指纹；重复章名以序号区分。
- [x] `tasks` 产出结尾倒序任务，正文带精确范围；回执包含 task/source/prompt 指纹、已读跨度、证据原句、观察及状态，空证据可合法提交。
- [x] `accept` 验证引句逐字匹配、跨度、指纹和引用关系；拒绝过期、错引或越过已读跨度的回执。
- [x] `build` 生成四表、覆盖/缺口、按状态隔离的关系图、候选 CASE；禁止推导胜败倍数或自动用旧态填结尾。
- [x] `verify` 复核来源、任务、回执及派生文件；缺片/未读返回明确 partial，不冒充全书精读。
