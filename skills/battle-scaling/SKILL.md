# 全自动论战与量级评定

由宿主 Agent 自动完成搜证、原作阅读、建模和裁决；配套 Python 执行可复算工具。开始后持续推进到有结论、出处、推算和反证的报告。缺参数时采用有依据的合理假设；缺原作时继续找可核验版本并标明覆盖范围。

公开源码版保留既有规则表、来源指纹与校勘记录，**不分发310页原始OCR、截图、小说全文或模型**。有限量级和高层计算不依赖可选OCR；手册逐页检索/回图需用户自行取得对应资料。缺项时按工具提示从显式本地目录导入锁定哈希的OCR，不自动下载，也不切换旧规则。案例中的图片文件名及本机来源路径只是历史定位，不能据此声称已读取当前不存在的图片。

## 入口与路由

1. 将包路径记为 `SKILL_ROOT`，运行 `python SKILL_ROOT/scripts/battle.py doctor`。确认宿主搜索与视觉工具实际可用；纯文本宿主使用 [外部视觉协议](references/tool-contracts.md)。工具缺项时先用现成替代，不宣称已读图。
2. 固定作品、连续性、时期、状态、装备、人数与任务。**小说默认评结尾状态**（完结本取最末时间跳跃后的状态，连载取已核最新章节状态）；按 [小说倒序取证](references/novel-ending-state.md)先查结尾、再逐项向前补证，不能把中期输出、早期弱态和后期装备混成结局配置。用户指定其他时期时按其指定。未指定模式用**常态**；要求对照时运行三模式。其他缺项采用并展示合理默认或分支，只有角色根本无法辨识才询问。
3. 按 [证据协议](references/evidence.md)找原作及反例；复杂角色、长篇或资料不足时加载 [搜证计划与索引](references/research-workflow.md)，用 `research` 生成逐属性正反证任务并按版本/状态检索。初次定档查 [全量级导航](references/tier-map.md)。默认规则为用户提供、扉页日期2026.7.30的汪峰在吧量级参考册；需要汪吧定档时读取 [量级册检索与校勘协议](references/handbook.md)，按需搜索310页索引并回看决定结论的原页。漫画/影视加载 [媒体阅读](references/media-reading.md)；涉及尺寸、受力或能量时加载 [物理模型](references/physics-models.md)；无限、叙事、论外加载 [高层构造](references/high-tier.md)及 [实际案例](references/high-tier-cases.md)。不预加载全册或大型模型。
4. 建立 [证据包](references/case-format.md)。新采集的单次输出、受击或失败表现，先按 [单次表现审查](references/feat-review.md) 核对因果链、实际出力、材料与工况、疲劳/伤势/资源/形态、战意/留手及声明性质；用 `feat_reviews` 保存审查，以 `review_requirements` 绑定依赖它的锚点、叠边与定性判断。材料无关的直接表现无需填全材料表；已知破坏结果不自动等于全力或全盛上限。再调用所需 `physics`、`high`、`media` 和 `sources` 工具，保存观察、文献参数、假设及中间值。复杂物理表现或叠链加载 [推导账本](references/derivation-workflow.md)，用 `derivation` 检查参数绑定、跨状态传递与高层证明；将缺口回送搜证，不把工具审核当作原作语义证明。
5. 单人按 [模式与传播](references/modes-scaling.md)生成属性，并按 [角色量级卡格式](references/rating-card.md)交付；**默认首句“角色（版本）量级：具体常态主档”，随后列常态九维，最高与扒下限只在其后的分析中提及**，用户明确指定其他模式或三模式并列表时按指定。固定包含**输出、体防、智力、战斗智商、经验、特殊技能、破坏、速度、体量**，每项给判定、原作出处和叠法。对战加载 [判胜协议](references/matchups.md)：**默认宏观推演**，给胜负倾向、合理胜率估计/区间及关键条件；仅当用户明确要求“具体战斗过程/详细战况/怎么打”时，加载 [过程推演](references/combat-process.md)，逐步写行动→发动/命中→防御/反制→伤势/状态→下一步，最后给短叙述。两种呈现独立于三种取证口径；只给故事不算完成。
6. 运行 `python SKILL_ROOT/scripts/battle.py analyze --input CASE.json --mode all --output RUN_DIR`（单模式替换 all）。默认 `--pk overview`；显式过程用 `--pk process`，须提供相应模式的因果轨迹。审核报告能否从每个结论追到具体原作位置；交付 `report.md` 和完整 JSON。本次报告放用户工作目录；站点经验按下述授权写入独立累计库。

每次实际在线搜证，先按 [站点经验档案](references/site-experience.md) 查询已知作品/资料类型和读取方法，再验证本次目标页面。用户已授权自动积累：每批实际访问后记录成功、受限和失败，保留真实回执、观察日期、分页/乱序/缺页等坑点及可复用查询方法；任务交付前检查是否已落档。`sources` CLI自动记录传输回执，HTTP成功不代表正文可读；宿主浏览器/搜索读取由Agent按回执调用 `sites record` 补记。旧成功不冒充当前可用，一页失败不封禁整站，搜索摘要不冒充全文。累计库在 `data/site-experience/registry.sqlite3`（可用 `BATTLE_SITE_DB` 指向其他位置），不属于用户记忆目录；升级和包校验须保留该目录，不覆盖或按静态文件哈希判损坏。

长篇本地原文或已有 refpack 按 [小说拆书取证](references/novel-evidence.md)，调用 `novel` 建独立文本快照、按结尾倒序检索并读取章级上下文，保存原文件／抽取文本哈希、章名、行号和字符范围。`canon/notes/out/整书总结/例子/stylefit` 只作派生导航，不能凭文件名升级为原作；项目续写口径不覆盖所评原著。检索命中、显示片段和宿主语义已读分别记覆盖，不能把建索引叫精读全书。

需要整书逐任务阅读、断点回执、正反表现聚合与结尾九维缺口时，按需加载 [完整论战拆书流水线](references/novel-refpack-pipeline.md)，运行自包含 `scripts/novel_refpack.py`。宿主逐任务实际阅读、写回执，主Agent顺序 `accept` 后 `build/verify`，再进入现有单次表现、特能和物理审查；轻量 `novel` 接口继续用于盘点、局部检索和读段。工具不内置语义模型，不以建索引或哈希通过冒充精读或评级。

资料分散、装备授予或关系叠链复杂时，加载 [搜证分支与交锋档案](references/discovery-dossiers.md)：从角色扩到相关装备／招式／组织／日志附录，按需记录敌手实际交锋、属性归属和继承桥。PK同时检查反方最强可行胜路与翻转条件；内部四张证据表见小说模板，聊天先给常态单一主档，再给九项紧凑量级卡。本次吸收及保留差异见 [迁移边界](references/combat-absorption.md)；不以新材料悄悄覆盖已确认的规则。

## 三种口径

| 模式 | 执行规则 |
|---|---|
| 常态 normal（默认） | 表现高于冲突设定；同版本同状态取多数可信表现中的最高。重复支持的表现群优先；样本不足时明确只有暂定结论。 |
| 最高 highest | 允许孤例、极端战况、最强/同级设定和形容词强解释参与叠加；把属性扩张、范围扩张和出力假设逐项展示。覆盖论外及具名规则的更细分档。 |
| 扒下限 lowball | 主动找虚弱、受伤、破防、失常输出、下位击败和缺少应有表现，反向叠至最低可论证分支；保留当时状态与“已尽力/有机会”等前提。 |

三种口径可激进取材，原文和计算记录始终真实。已观测到护盾承受的攻击属于护盾证据；若另一种解释有争议，建独立假设分支。没有明确倍数不逐跳升级，不以循环自举，不混用互斥峰值配置。

特殊能力按用户确认的 [双上限规则](references/hax-ceiling.md)：**默认取该能力表现内的影响上限；最高不得超过原世界观最强角色已达到的量级**，三种模式均适用。世界观结构高度不能替代角色已达证据；世界最强档位也不自动赋给每项特能。施术者肉身AP不直接封顶其特能。新评特能或依赖特能的PK路径，须建 `hax_checks` 并以 `hax_requirements` 绑定判断；仍独立审核适用对象、跨作品兼容、发动和抗性。未知则补证或给允许范围内的条件结论，已知超限不能用最高模式或假设绕过。

## 完成标准

聊天默认顺序为**常态单一主档 → 常态九维卡 → 来源与叠法分析（此处才讨论最高、扒下限）**。首句使用“角色（版本）量级：具体主档”，如“原子武士（村田版）量级：标准爆楼”；此句只示范用户要求的格式，不是可复用的角色证据。主档落到适用规则已有的细分档，例如弱爆楼、标准爆楼、超爆楼；区间、“楼级”或“以上”放在后续不确定性说明，不能替代最终主判。暂定或条件估档的限定紧随其后说明，标题不使估算升级为已证；总档也不自动覆盖体防、速度等属性。**九项各写明确主判档名/等级**，直接表现、参数与条件放在出处/叠法列。合理估计可以落暂定主档；已证、估算、条件分支须标清，不能为了填爆×档名忽略尺度/机制或捏造证据。三模式内部保持独立、按相同版本、状态与配置比较；默认不在首句或九维表并列展示。用户明确指定模式或三模式并列时按其指定。可添加力量、控制力、耐力、射程、恢复/抗性和弱点；计算与完整证据另附可复算文件。物理输出/毁伤使用已核汪吧档名；智力、战斗智商、经验等没有已证统一汪吧档位时给表现支持的能力等级描述，不能编造“爆楼智力”或冒称外站分档是汪吧标准。九项不可因缺乏焦耳值而省略，也不能只给角色一个总档位。

报告首段给出结论、模式、版本和规则来源；随后给属性、证据位置、参数/公式/代入/中间值、逐步叠加、关键假设、反证、获胜条件和覆盖缺口。N/J/W、移动/反应速度、肉身/护盾/抗性、世界观结构/角色能力分别记录。新册规则配置见 `rulesets/profiles.json`，分析报告锁定规则及原件哈希。有限定档核对能量、尺度、释放形式与多次攻击例外；缺条件时给条件参考。历史粗表仅通过显式旧版配置复算。高层逐项标明新标、道标、力标等口径，不混档；OCR字符和公式均作为资料候选，关键符号回原图校核。

每项关键表现注明“当次已做到／合理条件估计／全力或上限已证／待核”。疲劳、全盛、战意、杀意和实际出力分别判断，不凭表情或“无杀意”设置百分比；作者陈述核身份、原文语境与适用版本，角色台词核认知与旁证，合理推测列前提、替代解释和撤销后的影响。旧包未做新审查时如实披露覆盖缺口，不能把兼容读取称为已审。

## 工具与学习材料

运行 `python SKILL_ROOT/scripts/battle.py --help`，具体 JSON 输入见各分支文档。`assets/source-ledger.json` 提供研究入口，[案例索引](references/case-index.md)列出原有9份案例；新增双模式PK合成示例见 [补强来源与边界](references/external-ideas.md)。阅读时区分真实作品证据、条件估算和合成回归夹具。新表现使用同一证据结构扩展模型，先核对公式适用域并验证数值，再将新模型用于角色结论。

本轮仅吸收九个外部项目的目的、资料结构与流程，**不调用它们的模型或训练权重**。搜证、读图、行动选择与机制解释由当前宿主 Agent 执行；配套代码负责索引、运算、状态结算和审计。胜率是带前提的主观推算，不来自排行榜分数、分支计数或未经校准的公式；若无法合理量化，先给最可能结论和能翻转结论的条件。
