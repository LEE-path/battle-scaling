# 定档完成性：候选比较、推导归属与撤回

单人定档和三类PK共同使用本协议。具体档名、九维齐全、工具`ready`及宿主写了`accepted`，都不能代替实际选档审核。先按所选标准为当前配置完成统一综合评级，再以该评级约束对战；不能先选结局，再把尚未处理的证据称为不影响故事。

## 已证地板和综合主档分别验收

一次推搡、碎墙或旧招式可以建立具体的**局部表现下限**，却不自动代表该角色所评时期的综合量级。`basis:lower_bound`描述结论的证据性质；它不能说明较高可信表现已查完，也不自动取得PK资格。

1. **核对所评配置。** 从该版本最近阶段的实际能力、攻击、防御与变化入手，再按继承证据补早期材料。不能因旧片段容易量化，就漏掉新作品的实战；小说继续从结尾倒序建档，首次缺完整档案先拆书。
2. **盘点主要候选。** 同时寻找物理及特殊能力的实际表现、可靠设定、主要对手和共同参照、装备实绩、有效正反叠链及会改变属性归属的能力；按[综合主档与机制输出](rating-card.md#综合主档与机制输出)比较完整配置。对较高、较低和相反证据逐项判断，不要求穷尽全网、把每个场景转成焦耳或无差别拉长所有关系链。
3. **综合比较后选档。** 同一配置只给一个综合主档，联合审查可信表现、可靠设定、本体／机制及正反叠链。高光、通常与受限只作表现和交手参考，不分三套人物量级；不机械取最小、平均或全部峰值。VSB保持其自身异常表现、计算与叠链门槛。不成立的高链具体排除，不为纠正低估自动升级。
4. **给每条重要候选明确处置。** `adopted`说明怎样进入哪个属性的主判；`excluded`给出具体的版本、状态、机制、归属、参数或证据失效理由；`open`列仍缺的桥及其影响。已知可能改变所选档或关键属性的候选仍未审完，评级就是部分研究，不准冒充完成。
5. **保留合理暂估。** 定向覆盖及候选处置已经完成，只剩未穷尽上限、非关键精确值或已判定不适用于本模式的条件分支，可以采用有据的具体暂估或下限主档。不能因为没有官方精确J而永远不落档，也不能把“有一个具体J”当作结束研究的理由。

有限工具的`energy_reference`及`proves_character_property:false`只说明能量参考，不能取其档名直接填写已证角色主档。先补材料／尺度或合法属性桥，再形成独立角色评定；工具所需规则条件仍按当前标准执行，不能把汪吧条件强塞给VSB。评级未完成时先明说“部分研究／尚未完成正式主档”，将数值参考另列，不能沿用完整评级的首句模板制造已定综合主档的印象。

“保守一点”“故事够用了”“反正这个人会赢”“算不出精确值”均不能单独构成排除较高候选的理由。若已审明一条激进参数链不足以支持综合主档，可将其明确排除于综合主档、保留在条件说明中；不必为已完成处置的分支无限搜证。

## 完整对象与计算覆盖

原作完整对象、公式实际计算的对象、角色已建立作用／存在关系的对象必须对应。沿用既有来源、节点、推导及选档理由核对，不另强制填写一套表。

1. **先展开会改变主档的完整关系。** 一个已算层级之外还有整体超越、闭包、基底重置、权限或本体变化时，继续核对其对象、范围及角色关系。区分实际质差与单纯包含、容器、比喻或同层地点，不能漏算，也不能每见一次“外部／包含”就再加一层、无限因子或基数。
2. **给未覆盖部分真正的处置。** 计算只覆盖子结构，就将该结果标为子结构／下限；完整主档须另以有据模型、原生比较或所选规则解释剩余重要关系。没有合适公式时仍可作有原文约束的合理语义估档，不要求原作使用数学专名。只说“更高原生优位保留”却不说明它如何影响选档，不算完成。
3. **同档也要说明覆盖。** 完整关系审完后仍可落在同一具名档，但要交代所用模型、档内差别及为何该档代表完整配置；不能仅凭外层数目有限或工具只返回此档作结。主估不等于精确上限，子结构的可数性不自动传给整个对象，也不证明更高候选已被否定。不得为补偿漏算强造幂集、阿列夫后继或新档名。
4. **未决按实际影响收束。** 只缺非关键精确值时可交付明确条件下的完整主估；仍有会改变主档的重要关系未处理，按既有`partial/open + material`记录并继续补证，不以九维齐全、脚本通过或旧验收放行。来源采纳、数学解释和作用范围按证据比较，高光／通常／受限标签本身不是改档论证；未成立的额外桥也不是对原生关系的反证。

## 先证明归属，再比较数值

每条实质桥使用既有[单次表现审查](feat-review.md)、[模式传播](modes-scaling.md)及[推导账本](derivation-workflow.md)，分别核实：

- **谁造成了什么。** 区分本人、队友、合击、先前损伤、目标主动动作、环境与特殊效果。合击未有拆分依据就保留为合击，不把总量全记给一个人的单次攻击。
- **传的是哪个属性。** 伤害、防御、举力、移动、能量、控制与抗性分别处理。电击、绕过防御或特殊机制造成的胜利不能直接换成单人拳力，但须审入相应机制输出及综合主档候选，不能以“不是拳力”为由置于技能清单后不计；能对抗某一普通成员不等于继承该族最强个体的全属性。
- **当次状态是否匹配。** 比较具体出力、部位、伤势、留手、装备与时点。对手会一个大招，不等于这次每一拳、每块铠甲都承载该大招总能量。
- **模型是否有证据约束。** 观测量、文献参数、合理主估和自由变量分别留档；整体平移、旋转、局部变形与主动反应不能混算。先检验可归因比例及敏感性，再评跨档；不能为了过某门槛选一个便利密度、速度、体积或贡献比例。

阈值反推只用于识别缺口。例如某模型只有在攻击贡献比例`α≥0.428`时到达某档，这说明该档依赖此条件；未证明`α`可合理取到该区间，便不能把`α=0.5`包装成已证常态。公式正确、图像已读、制作方给了整体尺寸，都不证明全部目标运动由这一击贡献。缺参数时主动找替代参照或独立锚点，不能拿任意小数字敷衍，也不能拿任意大数字补偿。

## 重大改判与状态一致

主档或关键属性实质改变时，在现有报告说明旧／新评定范围、增删或重认的来源、仍成立的原生事实、变化的解释／规则桥及受影响属性。宿主沿决定主判或重要候选取舍的链，回读关键原文上下文并复演“来源身份→原文关系→解释前提→具名规则→角色特定属性”；代理完成、零错误和九维齐套均不替代此项。

降档与升档使用相同证据门槛。某个高层形式化尚未成立，只撤销依赖该桥的映射；不能反推其原生结构只到某个低档。保留竞争解释及具体处置，局部物理地板和较容易计算的子结构不能因此接管综合主档；也不以旧结论或用户期望代替新论证。

验收后统一report、rating、completion_review、host_review及输入中相应声明的当前状态与完整同一revision。沿用既有`complete`、`accepted`、`partial`、`withdrawn`等合法状态；合理估档的条件放`basis`、`assumptions/conditions`与理由中，不新造通过枚举，不以报告末尾一句接受覆盖JSON中的pending/partial。历史审核另存版本记录，已撤回或被替代的主档不能继续当作当前结果。只重算受来源、模型或规则变化影响的产物，未变证据不重复抓取，未变运算不重复运行。

## 综合主档不能由计算下限代领

若只算出了局部结构的指数塔或某个焦耳下限，而已知尚有整体叙事闭包、基底重置、书写权限、重要能力或更高可靠比较关系，则**综合定档尚未完成**。须将这些关系实际映射到候选、解释其影响并选定主档；写“外层优位保留”“暂作下限”不能替代处理。确有依据的下限只以局部结论交付，不冠完整综合评级，不据此制造角色上限或PK胜负。

已审完完整对象及主要候选后，综合主档仍可具有下限／估算性质；须解释为何它能代表完整配置。数学可复算、表格齐全或脚本通过，只验证相应片段／结构，不证明已完成这项语义工作。

旧三态的accepted/complete记录不是综合验收。新报告以`mode:integrated`和当前修订保存综合选档与实际宿主审核；`selected_basis:mode_representative`保留为兼容字段，现指代表完整配置的综合判断，不恢复三态。未变证据和计算复用，不把旧行机械改名后宣布完成。

## 共用完成性记录

每份`independent_ratings`角色行附`completion_review`，与报告中的实际审核一致：

```json
{
  "status": "complete",
  "revision": "character-v1-integrated-r3",
  "selected_basis": "mode_representative",
  "scope_findings": {"reasoning": "本次实际核查的版本、近期能力与继承范围；明确覆盖限制。", "evidence_ids": ["S-scope"]},
  "selection_findings": {"reasoning": "为何所选主档代表当前配置的综合量级；已证地板与主要候选如何比较。", "evidence_ids": ["S-feat", "S-comparison"]},
  "candidates": [
    {"id": "candidate-1", "affects": ["输出"], "disposition": "excluded", "impact": "material", "reasoning": "此处排除将两人电击总战果全归本人的单次物理AP；实际特殊作用及其本人贡献仍进入对应输出子项和综合主档审查，不抹去原战果。", "evidence_ids": ["S-comparison"]}
  ]
}
```

以上为格式说明，示例理由不得自动套用给真实角色。`scope_findings`与`selection_findings`必须来自本次实际研究；不能由程序批量生成“已完整核查”。主要候选没有额外争点时`candidates`可为空，但要在选档说明中交代实际比较基础；作者完整原创设定可直接作为依据，不虚构不存在的原作候选。

- `status`只有`complete`可申请准入；`partial/withdrawn/superseded`均拦截。
- `selected_basis:local_floor`只承认局部地板，不能充当完整评级。完成比较后有充分依据的下限主档仍可用`basis:lower_bound`和`selected_basis:mode_representative`，两字段回答不同问题。
- 每个候选有唯一`id`、受影响的九维字段或`main_tier`、`adopted/excluded/open`、`material/non_material`、来源与理由。`open + material`必定阻断；不能为了过门擅改成`non_material`。仅影响本场情节很小，不足以证明它不影响角色主档。
- `host_review.reviewed_revision`必须等于本次`completion_review.revision`。综合评级政策、配置、来源或主判实质改变时更新修订号、重审依赖的PK与战斗正文，不能沿用旧验收。

## 撤回优先于旧验收

复用前实际打开角色档案的**当前状态与最新复核**。已撤回的主档、旧`accepted`、历史`ready`、旧胜率和故事都不再证明当前评级合格；原来的单次计算可以按原条件保留，不能悄悄重新升格为综合主档。

将最新状态合并到PK输入顶层`rating_status`。例如本场任一必要评级撤回时可提供：

```json
{"status": "needs_research", "accepted_complete_integrated_ratings": false,
 "revisions": {"a": "a-integrated-r3"}, "current_review": "角色档案/最新复核.md"}
```

`status:current`才表示提供的状态允许复用；`needs_research/withdrawn/superseded`或明确否定综合评级完成的标记覆盖旧行中的验收。若提供`revisions`，须绑定当前参战角色修订号，缺项或不匹配先补核。无此状态表的原创小案例可以只用当前行审核；有现存状态档就必须读取并传入，不能省略已知撤回信息。旧包缺完成性记录时返回补核任务，禁止自动填`complete`迁移真实评级。

共用脚本只验证**已提供声明**的结构、修订绑定、来源引用和显式冲突，不会自动寻找所有外部撤回，也不会判断理由是否符合原作。宿主仍须读来源、检查推导和覆盖。工具通过与语义正确分开报告；不能承诺程序消除了所有判断错误。

## 本次失误对应的防线

刀灭霸／个人电影末尾闪电侠案例中，低位局部模型曾被充作完整综合评级，高位物理链与新作品攻击未充分审核；复核后原主档已撤回。此处只保留方法教训，不写入新的角色档：

- 旧模型有数值和九维卡，不证明常态选档完成。
- 漏查较高实绩后，不能简单改用另一个未经约束的高模型。
- 巨型目标主动动作不能全部归因于受击；双人特殊攻击不能全转单人物理AP。
- 撤回后应使旧包重新检查失败，并撤回依赖其完成性声明的胜负置信与正文验收。

验收同时使用负例和正例：缺审核、重要候选未决、局部地板冒充主档、撤回及修订错配必须阻断；合法排除高链、覆盖后仍只得到下限、非关键上限未定、VSB独立口径和完整作者设定应能放行。不会把“升级越高”当成修复成功。
