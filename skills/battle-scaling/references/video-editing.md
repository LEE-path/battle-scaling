# 本地论战卡点视频

缺角色图片／视频时加载[角色媒体搜寻](media-sourcing.md)，先按开场、底板、高光、收尾搜集并取得真实素材，再导入工程；媒体搜寻不启动新的评级取证。

合理补搜后仍缺少可靠角色图像时，按[稀缺角色素材](scarce-character-media.md)固定原作依据下的形象，再选视频API／CLI、本地H3或多姿态图片动效；后端配置和本地资源要求须先说明，不自动下载模型。

仅在用户要求论战视频、属性比较卡点、套用音乐模板或自动剪辑时加载。正式视频接受匹配配置的严谨普通PK，或先复用严谨独立评级再完成普通PK；按[视频维度比较](video-dimensions.md)只补所选展示项的实际缺口。两种起点最终都给总胜者与获胜难度，故事胜局与作者指定结局不能直接导入。上游研究完成后，媒体只接收其结论，不重跑评级、叠链、数学验收或全项目测试，也不按赢项数投票。

用户提供新参考并要求学习／复刻模板时，转[模板复刻](video-template-replication.md)完整拆解并实现，不只提取音轨或套已有版式；新模板先作可选项，现有九方案默认池保持。只制作既有模板的视频时不重复复刻流程。

## 工程与调用

**默认九方案，先抽再做。** 新的视频制作请求未指定模板或音乐时，先运行下列`select-template`，从V01—V09等概率抽取一个；将返回的`templateId`和`templateSelection`保留在本次任务。然后依据该方案挑选展示维度、音轨和素材，不能先按自己熟悉的版式制作再补写一个随机ID。修改同一工程、刷新预览或重渲染沿用已选方案，不重新抽签；下一次新视频请求再抽一次。用户指定方案／音乐时优先指定项。不因抽中后素材不足而偷偷换方案，先补其所需素材。

```powershell
python scripts/video_studio.py select-template
# 明确指定时：
python scripts/video_studio.py select-template --template V05
```

默认池与字号在`assets/media/video-presets/defaults.json`；九套可移植的时序在同目录`timelines/V01.json`—`V09.json`，入场与动效参数在`presentation.json`。只按需读取抽中那一套。音轨和人物素材仍从已有媒体库或使用者资源取得，未随这些参数分发。方案仅提供呈现，不继承参考片人物、给分或胜者。

正式制作默认走工程的`nine-templates`渲染器，使用与九条研究样例相同的呈现组件，并从当前任务读取双方素材、维度比较和总胜者。`FullV01`—`FullV09`是参考研究样例，不能直接拿原案例替换一次人物名充当新对局。旧工程保留原渲染方式。

使用独立的Battle Video Studio本地工程（Remotion＋FFmpeg）。入口`python scripts/video_studio.py open`；`status`查看连接、可用音乐时序和导出进度。工程位置依次取`BATTLE_VIDEO_STUDIO_ROOT`、`runtime/video-studio.local.json`或Skill相邻的`battle-video-studio`目录。未配置时指出需要的工程路径，不自行改宿主配置或把重依赖装进评级环境。

把本场结论编成工程的任务JSON：双方显示名/版本、素材列表、按页比较项及揭晓者、最终胜者、音乐模板与样式。用户给自然语言/表格评级时由Agent理解后填入，不要求用户手写JSON。保留完整评级位置，媒体只选上屏内容。任务格式、素材入出点与构图焦点见工程README与演示任务。

```powershell
python scripts/video_studio.py prepare --job "任务.json"
python scripts/video_studio.py render --project "工程ID"
python scripts/video_studio.py status --project "工程ID"
```

`render`提交后立即返回；根据进度观察完成或错误，不开一个长期静默命令等待。未变的音轨时间表、素材元信息和已准备工程直接复用。只在用户要视频或明确允许演示出片时渲染，不在每次评级后自动剪。

Skill的`prepare`优先调用工程当前CLI，读取磁盘上的最新编排器并返回简短JSON/结构化素材缺口，不依赖已运行服务中的旧模块，也不为升级中断浏览器或工作台。`--no-activate`可准备独立试用工程而保留当前预览。工作台的手工HTTP入口在该服务下次正常启动后加载更新；已运行的预览与导出进度可继续使用。

## 实际候选编排与缺口处理

宿主先实际查看并评档、标有效入出点；工程`prepare`会生成每个scene的可播放素材区间，不再在渲染时凭角色数组随意取第一个finish。优先保留只有少数候选的用途，再规划开场/底板/两段揭晓/长尾，避免灵活开场抢掉唯一收尾。底板循环及短揭晓轮换保留，其余跨用途按源片区间不重叠。

最小候选例子：`{"path":"片源.mp4","role":"finish","trimIn":71.2,"trimOut":77.6,"qualityTier":"S","excitement":"exciting","continuous":true,"allowSlowdown":true,"qualityReason":"实际连续查看，人物和装备完整，动作有张力"}`。没有新增数值评分。预裁片/变速片另外说明`sourceId/sourceIn/sourceOut`；`cropUsable:false`不使用，优质图片可注明`displayDuration`，不无限延长兜底。

实际长展示按既定六级顺序择优，能用精彩长段就不切碎；精彩原速短段优先于靠降速凑长。规划尊重最低0.5倍边界，不改变音轨/卡点；新任务不把不足段循环成开场或长尾。源片身份、精彩程度、水印可裁切性和内部切镜仍由宿主视觉判断，程序不冒称识别。

不足时返回`code:MEDIA_GAPS`及`gaps[]`，含角色、用途、所需/可用/缺少秒数和补素材建议。Skill桥会保留这些结构化信息，不只给一句失败；按缺口补入出点或候选，再准备相同工程，不重评角色、不重抽模板。同ID未给templateId会继承已抽方案，只有明确换模板才更新。

详细JSON及接口以可选工程`docs/media-planning-api.md`为准。旧compiled无媒体计划仍可打开/渲染；重新prepare采用新规则，不静默保留超出慢放边界或明显重复的新编排。每次导出独立文件名与临时bundle，播放器占用旧MP4不妨碍下一版，错误进度保留上次成功输出。可选包不分发参考音轨；先用工程`import-music`命令导入具有使用权限且对应所选模板的音轨，不能只找同长度歌曲替换而沿用原切点。

## 默认结构与素材分工

**具体模板优先，通用结构只作选材基准。**先读所选模板绑定的音轨、`stages`、比较／揭晓切点和参考画面，明确每个时间段采用全屏、分屏、双方轮流登场还是单人高光；再准备本场素材。不同模板的展示段落、版式、长短与切换方式分别执行，不能只取某条音乐，再套另一条的镜头结构；更不能仅凭相近BPM混用时序。

例如V05“超人vs祖国人”的0—9秒是双方全屏轮流展示，之后才进入维度比较，23.13—54.1秒另有较长赢家高光；不能把开头改套V09的双人分屏。V04有较长交锋附加段，V06／V07没有同样的独立长胜者尾段，不为统一结构给它们硬加时长。总胜者及难度仍在该模板可用的结尾位置清楚呈现。

下面是跨模板的素材分工基准，实际布局、顺序和长度由对应音轨的编排决定；模板没有长尾时不强行增加。每人两段揭晓等选材偏好可以沿用，不能据此移动卡点或改变音乐。

| 段落 | 默认制作方式 |
|---|---|
| 开头双方长展示 | 精彩长段优先，其次几个精彩短段；不能为连续和够长而选择拖沓场面。身份、能力、装备与气质清楚，节奏贴合对应乐句 |
| 中间维度比较 | 双方各选一段稳定底板，固定成同一套分屏短循环，变化主要由维度文字与卡点承担 |
| 每项结果揭晓 | 双方各准备两段通过[即时辨识硬门槛](media-selection.md#维度揭晓的即时辨识硬门槛)的不同单人短镜头；看不清或难辨身份即排除，S档也不豁免。按该角色自己的获胜次数轮换，不按全局维度序号取奇偶；不以不合格第二段凑数 |
| 末尾总胜者长展示 | 显示胜者姓名与难度；精彩长段→几个精彩短段→拉长的长段→普通短段→多个动图动效→多个图片动效，依观感择优 |

**长展示的素材不重复，也不与其他位置重复。**开头、比较底板、单项揭晓、片尾分别选材；长展示内部不得反复播放同一镜头，开头已经用过的画面不再放到中段或片尾，片尾也不复用中段素材。中段固定底板循环与每人两段揭晓轮换，是本结构明确保留的重复。复用同一源片中的不同、不重叠镜头可以；换文件名、裁切、镜像、调色、变速或错开少量帧，不会将同一个镜头变成新的素材。按镜头和源片区间分配即可，不增设去重验收表。

素材不足时先补搜合适镜头；**合适的画面可慢放至最低0.5倍速，最多延长为原时长两倍**，但这是允许的边界，不是默认做法；几个精彩原速短段优先于靠慢放凑长度的长段。慢放后仍应流畅、主体清楚、动作有气势；口型、喜剧时机或过快动作不宜硬拖。单段和多段组成的长展示均可这样匹配时长。画面降速不改变音乐及已标定的维度／揭晓时序；不足部分继续补素材，或用独立的优质图片动效，不以重复长展示、低于0.5倍速、反复来回播放来凑长度。两段揭晓素材也先择优补齐，不为凑数塞入明显较差镜头；实在只有一段好素材时如实说明后采用现有兜底方法。

制作长展示先按[干净片源与精彩优先](media-selection.md#干净片源与精彩优先)选材。确需拼接时，可用FFmpeg将已选的不重复片段变速、统一画幅／帧率后拼成一条播放素材；保留源片与入出点，拼成一个文件不会提高原生连续性。不依靠短片段循环填充。单条足长入场素材不要被通用默认切点反复重置；明确使用`introCuts: []`连续播放，或按该模板实际编排设置入场切点。中段分别用`plate`和两条`highlight`，末尾另用未在前段出现的`finish`素材。播放长度以实际导入素材为准，避免容器时长舍入引起切点回卷。

九套默认方案分别调用对应的入场、比较、揭晓和片尾呈现；V05采用全屏轮播，其余按各自分屏入场。制作时按当前任务准备对应素材，不能把原素材中的动作、发光或表情当成动效模板会自行生成的能力。只处理本次抽中的方案，不为一条视频重做全部方案。

## 音乐、维度与素材

**视频标识与参考适配**：从参考视频学习时，借鉴入场时点、转场和片尾呈现方式，不沿用参考作者署名。模板默认项目标识为Battle Scaling；开场使用选定的透明VS图片，对整张图片执行渐入、缩放或其他对应入场动效，文字／字体版VS只作可选，不因参考片用文字就覆盖已选图片资产。无VS入场的模板不硬加。片尾使用项目署名并保留原有动效；源片作者名只留在来源记录中。原始素材内嵌角标不作为模板水印资产，正式选材优先清晰、合适的原始片源。

- 视频文字默认采用得意黑（Smiley Sans Oblique），人物名、状态小字、维度、胜者／难度、片尾署名与水印统一相对模板基准放大一档，即`textScale: 1.15`；这是一份固定默认值，不在重复制作时累乘。图片VS仍使用原资产的比例与入场。工程随附字体与 OFL 许可证，预览及导出加载同一文件，不依赖系统安装，不额外合成粗体／斜体。用户另指定时按其选择。

- 视频开场中央VS默认01银白断锋；02黑白墨裂、03冷棱切面、04赤白漫画为备选，随包素材在`assets/media/video-vs/`，工程用`style.vsVariant: silver|ink|prism|comic`切换。直接叠原生透明PNG，不再用黄色文字代替。此偏好只针对视频中央标记，PK海报默认版式继续按封面模块选择。

- 素材先按[用途与优先级](media-selection.md)选过再导入。工程在兼容用途内读取`qualityTier: S|A|B|C|unrated|exclude`优先选择好素材；底板固定，单项揭晓在已择优的不同S/A候选间按该角色获胜次数轮换，其他用途优先最高档。A档图片优先于B/C视频，排除项不参与。档位来自宿主实际看图／片的判断，不是下载器认证。图片已有推拉、平移、轻旋转和切点震动，可承担视频位置。
- 片尾固定呈现胜者姓名与难度两行，字号接近；可选补充文字不替代两项。上游用`verdict.difficulty: no|low|mid|high|extreme`及短理由，显示文字可通过`difficultyText`本地化。编译器只要求制作所需结论齐全，不认证研究语义；参考／素材技术演示必须显式标记，不能冒充严谨PK。

- 时间模板绑定具体音频片段、起点、速度、比较展示位、揭晓位和尾段。默认先抽方案，再从完整评级挑出重要且有区别的维度匹配容量；用户明确指定维度容量或音轨时仍可按其约束选择，不凑同义项，不删除底层完整评级。
- 单独胜者页不计入普通比较位。“优势/全面”是综合展示，“人气/梗”等是主题项。原片标签与给分仅作时序示例，换角色时使用本场结论。原片无独立胜者位时，可明确改用已有片尾呈现结论，不平白增加音乐长度。
- 默认池固定为这九套已整理的方案；更换音乐剪切版或变速时重新标定对应段落，不能只凭相似BPM套用。各方案共用底层呈现组件，独立保留时序、版式及动效参数；具体数值是对参考的实现近似，不声称还原原作者工程。
- 从准备好的素材或可信片源挑选对应版本的多个候选，按开场辨识/气势、稳定比较底板、短促单项高光和胜者收尾分工。按[镜头边界与主体连续性](media-selection.md#按镜头划入出点不能只看中间一帧)划入出点；优先主体清楚、动作有冲击、裁切后脸/核心与关键装备仍可辨。重复使用少量优秀短镜头合理，不必每项找独有画面。
- Agent负责有目的地挑场面和构图；工程按素材用途、指定区间与焦点自动排布/轮换。不要把机械轮换称为理解任意视频的语义选镜。参考演示里已有字幕或剪辑痕迹的素材不默认成为正式成片的优选素材。
- 动效随帧和切点变化，保持属性字与揭晓者清楚。效果强度服从音乐、素材和用户风格；不以加特效数量代替好剪辑。

## 交付

交付本机可播放MP4、可继续打开的工程位置及简短说明。工程是Remotion任务/代码工程，剪映或Premiere原生工程需另有已实现的适配器，不能混称。修改任务、换素材、调焦点或动效后保留新工程。

完成后看开场、比较、双方揭晓、总判和收尾，检查文字遮挡、构图、黑帧、声音和卡点；选段首尾、内部切镜及变速／循环／转场的接点前后也须实际看过，不能只抽中间代表帧。有问题只改对应片段。听觉能力受限时如实说明，不能把波形或文件存在当成已完成耳听。正常素材格式/时长处理属于剪辑操作，不迁入评级包、哈希回执、数学复算或全项目测试。
