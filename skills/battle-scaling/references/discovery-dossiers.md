# 载体检索、对手档案与反方审查

需要扩展资料载体、沿角色比较关系补证、核查关键交锋或对战裁决查漏时，按需加载相关段落。这里组织检索和证据，不设评分、概率模型或新量级规则；继续使用 [research](research-workflow.md)、[证据包](case-format.md)、[单表现审查](feat-review.md) 与 [判胜协议](matchups.md)。按相关性选择条目，不要求所有角色填满所有表。

## 五轴开局查漏

定级和VS先按[末期能力与实绩协议](ability-feats-and-combos.md)建清完整配置、逐能力正反表现和继承，不只核招牌技能。首次小说完整档案优先走[论战拆书项目](novel-refpack-pipeline.md)，下述换载体、逐章检索用于发现／补证，不能替代拆书。关键能力或实绩新增后重新评估双方组合胜路与反制；相关能力的载体、发动条件、控制权和支援关联也应作为候选作用目标。

| 轴 | 实际需要问的事 | 记录到哪里 |
|---|---|---|
| 载体 | 角色主条目之外，装备、招式、组织、附录、实验记录、逐章正文、官方前传／衍生故事、设定资料、主创原始访谈，或原作片头／回忆／背景展示是否有更直接入口？按相关线索选查。 | research 任务/线索、来源定位、实际访问回执 |
| 证据性质 | 是连续画面/动作原文、叙述/台词、作者补充、宣传还是社区解释？谁说、能否知情、是否严肃、适用哪版？ | `sources` 及 `feat_reviews.evidence_claims`；沿用实际 schema，不凭载体名给真实性保证 |
| 归属 | 本体、装备加成、能力授予、变身、融合、召唤、暂借、一次性外力分别贡献什么？离开来源还能维持吗？ | 独立角色/配置、`anchors/edges` 的归属、`review_requirements`、必要的条件桥 |
| 关系 | 当次是命中、承伤、吸收、豁免、破防、封印、撤退还是战胜？具体能传哪个属性，不能推出什么？ | `feat_reviews` 因果链、`edges` 的关系和条件、反例 |
| 结构 | 连续性、版本、时期、改编、多人创作分支和用户指定综合范围是什么？ | 角色与来源版本、CASE 条件、综合候选采纳／排除及状态适用理由 |

这五轴是查漏视角，不是强制从 A 到 E 的证据等级。官方宣传仍可能不能证明具体输出；社区页能提供原作链接但不因此变成原作；机构口吻的虚构日志不天然比同连续性故事更真实。用户指定最高综合时明确跨篇桥，不擅自改成“多数作者共识”。

## 换信息载体，再换检索词

角色名搜不到决定性原文时，沿可见信息走 `角色 → 装备/招式/组织 → 日志/附录/任务记录 → 对应章/集/页/格`，并反查对手及使用者。正文优先，社区条目与章节摘要用于定位；没有实际打开原文就标索引。载体不存在或与当前版本无关时跳过并记原因，不为完成清单硬找资料。

关键词随发现扩展，而不是只搜“角色实力/量级”：

| 线索目的 | 候选词，按原作术语与别名调整 |
|---|---|
| 作用/残留 | 破裂、穿孔、碎块、粉末、熔融、蒸气、坍塌、冲击、传走、消失、恢复 |
| 发动/限制 | 接触、视线、范围、持续、消耗、理解、标记、蓄力、只能、无法、代价 |
| 状态/出力 | 疲劳、伤势、资源、变身、留手、战意、全力、反噬；分别核，不用词频换出力百分比 |
| 能力/抗性 | 时间、空间、精神、灵魂、信息、概念、复制、吸收、适应；同时搜承受、破防、免疫、失败 |
| 装备/归属 | 获得、授予、借用、融合、召唤、持有、失去、离开、解除、消耗 |
| 对手/关系 | 谁挡下绝招、打伤谁、被谁控制、被谁制止、胜因是什么、何时能力无效 |

实际搜索前查 [站点经验](site-experience.md)，访问后自动累计真实方法和回执；公开 API/RSS/移动页只是候选入口，不能把历史可用写成当前可用，也不能绕过登录或验证。多个镜像复制同文不等于多个独立证据。资料不支持量尺、材料或损伤终态时继续查原图/工程资料，不默认用统一尺寸或混凝土常数。

## 对手与交锋档案

选择与主判、抗性上限、反叠或决定胜负最相关的对手，不设固定五个的门槛。每条交锋可用下面的工作行：

`事件ID → 双方ID/版本/状态/装备 → 原文定位 → 实际动作/出力 → 命中或发动 → 受作用防层/抗性 → 结果/伤势/恢复 → 留手/克制/偷袭/环境/队友 → 可支持属性 → 不可支持属性 → 待查前提`

可靠的定位／最强／同级等比较，核清集合、时期、配置与谓词后，主动连接参照对象的有效表现和设定，形成综合主档及相应属性候选；不只取集合内最低成员，也不要求被评者逐个交手或重演同规模破坏。综合战力与特定属性比较的传播范围，按[可靠比较设定叠链](modes-scaling.md#可靠比较设定的叠链)处理。实际打伤肉身不自动获得对手宝石输出；碰不到目标不等于力量不足；封印成功不自动变成拳力压制；承受后存活、无伤、护盾挡住、吸收与重生分别记录。数量、围攻与同场战绩不机械求和到单体 AP。没有明示倍数，不从秒杀、撑住或压制跳固定档。

**跨来源补成完整论证。** 表现、能力归属、比较关系与连续性桥可以来自不同合格来源，不要求单个页面包办全链；逐段保留原文定位、证据性质，并核对对象、状态、时点和可传属性。官方补充或主创访谈仍须核其身份、上下文与事实性质；原作片头、回忆和背景展示按实际叙事含义判断，不凭出现位置自动作废或认作实绩。后发表的资料可以揭示同一世界早已存在的能力，不能仅凭发表时间较晚排除；共同品牌、同名或同演员也不能自动接通版本。关键桥有依据时可作合理推定，真正缺失的前提明列为条件；单条来源受阻时按[缺口补链](evidence-gap-recovery.md)换来源或参照，不把未核线索改成已证事实。

检索以会改变主档或关键交互的关系为边界，不要求穷尽整个系列或无限扩展关系网。取到重要能力锚点后，按[通用判定原则](scaling-principles.md)并用适用的严格计算、可靠原生比较和有据语义估档，再按[定档完成性](rating-completion.md)比较重要正反候选；找到一个易量化的局部下限不构成收束理由。已成立的设定与关系不能仅因缺精确J、未有本人重演或某项计算未成功而被删除；合理估计不冒称精确实绩，九维及工具通过也不替代实际搜证与候选取舍。

**能力转移另建继承桥。**授予、召唤、融合、复制和暂借分别核：来源对象与版本、原文授予的具体能力/属性、数量或倍率、启动与维持条件、本人及随身物品能否独立维持、结束/解除/资源耗尽后的保留、限制与反例。文字“获得某某之力”不默认继承全部速度、体防、权限及所有时期峰值；存在强解释时保留具体条件分支，按[综合选档](modes-scaling.md)比较其可信度与适用性；不能把可靠继承仅放进“最高”另档。桥落 `edges/conditions/assumptions`，跨状态依赖 `state_transfer`，特能还需 `hax_requirements`。

## 特能攻防交互矩阵

按决定胜负的具体能力对构建候选行，不按“概念＞时间＞空间”等固定类别判胜：

| 项 | 记录 |
|---|---|
| 攻方 | 实际能力归属者、配置、当次用法、发动/命中/射程/持续与代价 |
| 目标 | 实际受影响者、对象类型、状态、对应层级与比较依据 |
| 两道上限 | 自身表现内影响上限；原世界观最强角色已达到的绝对上限；各自证据和规则版本 |
| 防方 | 对应防层、豁免/吸收/抗性机制、已承受对象与限制、是否能先手发动 |
| 兼容 | 跨作品对象/机制如何对接，原文或明确条件；同名不等于相同机制 |
| 结论 | 可行/条件/超限受阻/未定；来源 IDs、反例、待核和撤销假设的影响 |

实际 CASE 按 [hax 双上限](hax-ceiling.md) 创建并绑定 `hax_checks`，不把工作表当可跳过检查的结论。攻防均标实际归属者/目标；被阻断的特能路径不自动给另一方胜利，仍查独立物理或其他能力路径。世界观结构高度不替代角色已达，施术者肉身 AP 不直接封顶特能。

## 反方最强可行胜路

在主判形成前，主动给每方构造最有依据的获胜路径：`发现/接近 → 发动或命中 → 通过防御/抗性 → 造成失能 → 在恢复/逃脱前完成胜利`。对倾向败方，也找其最强合理分支并逐环核查；不能拿无来源的新技能凑“平衡”。

记录它依赖的原作证据、场地/情报/先手、状态和兼容假设，哪一步已受阻或未知，以及改变什么会翻转结论。撤销本方最关键假设再看主判是否仍成立；若双方各有真实胜路，报告解释选择主估的理由和不确定范围。不用完成多少条路径、哪个维度得分多来计算胜率。

宏观结果落 `matchup.win_paths`、`mode_assessments`、`critical_assumptions` 及已有 `win_estimate`；具体过程仅在用户要求时用 [combat-process](combat-process.md)。补充的反方说明可在本次报告附录，链接同一来源/条件 IDs，不能新建不参与审查的“已胜”标签。

## 交付前任务审查

用本次已有证据填写以下检查的 `通过/条件/缺口/不适用` 与位置。它是宿主逐项检查产物，工具只核结构/引用/读取状态，不认证语义：

- 版本、时期、装备、人数、开局范围一致；小说九项按同一结尾状态倒查。
- 末期能力清单及逐能力成功／失败、条件、抗性对抗、代价和延续均有实绩档案；小说已有合格完整档案，或已优先执行拆书并如实披露未完成范围。
- 组合打法逐环有表现和前提，实际发生与合理推演分开；已检查操作敌方能力／载体／发动条件的可行路线，补新关键证据后已重评整场而非只加附注。
- 九属性有主判及来源/叠法，未知与合理条件估计分开；不因缺焦耳省略属性或编造“爆楼智力”。
- 关键事实已读原文/原图，摘要、派生资料、作者声明、宣传与推测身份未混用。
- 视觉测量、材料/结构/破坏模式、因果和实际出力有依据；N/J/W/Pa/速度子项与体量承伤分开。
- 叠边可追溯且未机械升级；外力/授予/跨状态/跨作品桥展示范围、限制和前提。
- 依赖特能的评级和获胜路径都绑定双上限审查；条件不能绕过已知超限。
- 支持与反证、反方最强路径、翻转条件、恢复/逃脱窗口均已检查。
- 实际查询与读取覆盖、阻断、剩余矛盾、哈希和运行输入可追溯；未将索引/文件校验当作全书精读。

查询任务继续落 `research.coverage`，原文来源与证据链继续落 CASE 和运行目录。没有机械最低条数/最高条数；检查存在缺口时保留合理暂定主判及条件，不把表格填满本身当完成。

## 思想来源

来自用户提供的 combat-scaling 主流程（本地研究档案，不随公开包分发）、取证五轴（本地研究档案，不随公开包分发）、自主表现搜集（本地研究档案，不随公开包分发） 和反方论证模板的组织思想。源文件本机路径只作吸收来源，不是运行依赖。独立整合进现有框架，未复制其脚本/量级阈值、未引入模型、固定类别优先级、固定评分转胜率或跳档规则。
