# 角色量级卡：属性、出处与叠法

九维及“主档→属性→分析”的呈现两标准共用；本页的爆×档名、册内切点和特能双上限仅用于汪吧。VSB按 [属性与计算](vsb-attributes.md)区分AP/DC、打击、举力、速度、耐久等，主档写VSB代码＋官方名称，特能走 [VSB门槛](vsb-hax.md)，不做爆×词语替换。

单人评定与所有PK前置共用[独立定档流程](character-rating-workflow.md)。九维审查或几个表现摘录不能代替具体定档；主档及适用输出／体防／破坏至少给有证据和推导的完成覆盖及候选审查后的有据具体下限。精确J、kg或上限未定可另记，不能把主要属性本身留成模糊／未定并放行PK。具体下限也不单独证明完整综合评级：先按[完成性协议](rating-completion.md)审查近期实绩及重要候选，再选完整配置的综合主档；未处理的重要高位链、局部地板和已撤回旧档不能靠填满表格取得准入。

固定九项来自用户明确要求，不称全汪吧唯一模板。聊天先给一个综合主档，再给同一配置的九维表，来源和单句叠法放同行；高光、通常、受限表现只在依据及交手条件中分析，不生成三套角色评级。长计算、原文上下文、全部假设另附文件，不用长文代替量级卡。

## 默认回答顺序

1. 首句固定形式：`角色（版本）量级：具体综合主档`。例如`原子武士（村田版）量级：标准爆楼`，仅示范呈现，不是新的原作证据。
2. 紧随首句说明必要配置、暂定/条件性质及置信度，随后给综合九维卡。主档选定适用规则已有的一个细分档，例如弱爆楼、标准爆楼、超爆楼；范围、“楼级”及“以上”属于后续解释，不代替最终主判。册内“标楼”等规范名称可显示为用户要求的“标准爆楼”，保留原规则映射，不修改数值门槛或增造细分切点。
3. 九维之后分析原作证据、推算、叠法、条件峰值、失常／受限表现与争议；它们服务同一主判及交手评估，不另生三套人物量级。
4. 用户追问极端或低谷时，说明对应表现、状态、假设与交手影响；明确改变时期／配置则另评该配置，仍不以三态分档。总档不是全属性同档；各维度独立取证。合理暂估的条件不能被标题隐藏，也不能为了填档编造证据。

每行首先给**明确主判**：如“弱爆街（科技多束累计，估算）”“普通人级（肉身）”。“断臂击飞成人”“热毁小山”属于依据，不是最终评级。合理假设支持的档名可以作为暂定主档，假设在叠法列披露；纯能量参考要明确被评的是累计能量而非同范围毁伤。不得为满足爆×字样而把智力/经验硬变成能量档，也不得省略尺度、材质或慢释放条件。某物理子项确实只有普通人档证据，就在该子项明确普通人；只有完成全配置审查、没有更高有效作用依据时，才可把它作为综合主档。

## 综合主档与机制输出

默认按[通用量级判定原则](scaling-principles.md)处理证据、对象、关系、必要前提和候选比较，本页只规定如何把结果写成主档及九维卡。足够表现、可靠设定和有据推导均可支持相应关系；例子不构成准入清单。

汪吧综合主档比较当前配置全部重要候选，不取最低物理子项、不做九维平均、不只读取数值conclusions。机制或本体关系可决定主档，同时保留不同档位的物理子项；结果标明支持的是作用、能力还是存在层级，不能复制给全部属性。VSB按其Tier／AP和特能规则归属，不套汪吧综合反推。

首句仍给一个具体主判，紧接配置及已证／合理估计／条件性质；九维各项给相应档名或适用等级、出处和可复述推导。范围与未穷尽上限留在说明中，不以模糊区间取代主判，也不把本体定档伪装成已补齐所有PK属性。用现有定性主张、来源、推导及九维节点保存，不新增强制字段或要求所有命题伪造一次发动。

## 必列九项

| 属性 | 应回答的问题与评定口径 |
|---|---|
| 输出 | 单次行动／一次能力发动及其有效作用；分徒手、能量、装备与机制输出，包括创造、修复、转化、控制、改写、删除、降格及叙事结局作用。汪吧档名与J／作用机制分列，累计／持续注明时间和次数 |
| 体防 | 身体实际承受何种攻击、如何命中、有何伤；皮肤/内部、装甲、护盾、规避/转移、恢复和抗性分开。能靠再生/格挡/机动持续交战不直接证明裸身同档硬度；未命中不能记硬扛 |
| 智力 | 学习、记忆、推理、计算、知识与研发；区分本人、AI、道具或权限辅助。不伪造IQ，等级描述跟实际事例 |
| 战斗智商 | 临战判断、识破、试探、骗招、适应、资源及距离管理；用具体战况支持，不由科研智力自动继承 |
| 经验 | 训练、实战、对手类型、战争/团队经历与能力熟练度；寿命不等于有效实战时间，他人经验不因服从/同称号转移 |
| 特殊技能 | 能力种类、效果、对象、自身表现内影响上限、原世界观最强角色已达档、作用域、发动条件、抵抗/失效；按[双上限规则](hax-ceiling.md)评级。再生与特殊抗性可在此加子项。传送/抹除作用域不是同档拳力 |
| 破坏 | 实际物理毁坏或机制消除／毁改的对象、结构、范围、终态及时间；按用户要求与输出单列，控制成功不自动成为全域毁灭，总能量不自动补覆盖面积 |
| 速度 | 分地面/飞行移动、反应、战斗、攻击传播、载具旅行、传送/跃迁；每一子项采用其适用速度口径 |
| 体量 | 尺寸质量、生命／器官构造、承伤总量／血条，及已证完整本体规模／存在层级；游戏HP与现实人体分开。本体、分身、投影、代言和周围世界分别判断，不直接换J |

常用补充项：**力量、控制力、耐力/续航、射程、弱点**。力量区分举托/拉扯/角力与打击能量；控制力看精度、分配/集中、多目标与误伤。恢复、抗性、装备及常用战术在相关时展开，不为凑栏目发明结论。

特殊规则一次作用确实造成实质有效结果时，在“输出”行明确列机制子项及已证对象档／条件，并审查其对综合主档的影响；不因缺焦耳、没有物理伤口或不能归为拳力而另置不用。控制、转化、删除成功不自动复制目标全部物理输出或体防，也不换算同档焦耳；仍按 [双上限规则](hax-ceiling.md) 审查。内部可用 [四表模板](../assets/templates/novel-evidence-card.md) 汇总原文、能力和交战，不能用长表替代用户要的九项主判卡。

体量/动物/游戏资料逐字段保留 `value_status:known|unknown|not_applicable|actual_zero`、`basis:measured|documented|estimated|assumed`、数值与单位/区间、原出处、审核日期及适用的物种/性别/年龄/状态。`actual_zero`必须是有证据的0；未查到、工具不支持和不适用都不能填0。体型、器官/组织、受击部位、群体可接触人数与游戏HP分开记录；质量或HP更多不自动等于每一部位更硬。按需将字段原样入research索引，不用一个总分压掉适用条件。

## 聊天量级卡与表现参考

```text
角色（版本）量级：具体综合主档
必要的暂定/配置说明；统一评定时点与汪吧规则版本
属性 | 综合评定 | 原作出处 | 叠法或推算依据
九维之后：证据与推算分析；高光、通常、受限表现及条件解释在此说明
```

- 必列九项各有一行；速度等必要时加子行。统一采用上述综合表，不保留三套人物级别的内部捷径；表现对照可列证据、状态及结果，不把三种视角的最小／最大自动当作人物定级。
- 本人、常备装备、可选装备／科技、独立外援分别标归属，不在同一主档中无提示切换配置或把盟友防御当本人输出。
- 小说逐项标明“结尾直证／向前最近补证／延续推定／历史地板”，按[倒序协议](novel-ending-state.md)保留最近取证位置和更晚是否出现升级/替换。旧攻击地板不能代替结局综合量级，旧弱态须查延续／状态关系。
- 每行至少有稳定原作位置、可点击出处和能复述的传播链；同源可用链接式S1等索引，所指条目须有原作章/集/时间码及访问状态。写“某人强所以同档”不够，需保留属性、状态、实际出力及是否机制克制。
- 有直接表现就写“直接表现”；需要模型时给主估档与关键假设；缺参数先做有依据的保守估计并落到具体下限档。定性战果与条件区间放依据列，不替代主判；确实连具体下限也未证时说明缺口并继续研究，保持评级未完成，不省略整行或取得PK准入。
- 输出与体防等适用的项目用已核汪吧量级。未发现统一标准的智力、战斗智商、经验，用明确的能力等级/实绩描述，注明不是汪吧统一数值档。速度、体量保留适用物理单位；不能把九项全部硬塞爆砖至论外。
- 先给主判，条件统合／跨篇桥接列条件；没有无限构造就不凭“无数”直跳论外。论外适用时仍给逐步构造与原生能力桥接。
