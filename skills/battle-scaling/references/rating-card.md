# 角色量级卡：属性、出处与叠法

固定九项来自用户明确要求，不称全汪吧唯一模板。聊天默认先给常态单一主档，再给常态九维表，来源和单句叠法放同行；最高和扒下限只在其后的分析中提及。长计算、原文上下文、全部假设另附文件，不用长文代替量级卡。

## 默认回答顺序

1. 首句固定形式：`角色（版本）量级：具体常态主档`。例如`原子武士（村田版）量级：标准爆楼`，仅示范呈现，不是新的原作证据。
2. 紧随首句说明必要配置、暂定/条件性质及置信度，随后给常态九维卡。主档选定适用规则已有的一个细分档，例如弱爆楼、标准爆楼、超爆楼；范围、“楼级”及“以上”属于后续解释，不代替最终主判。册内“标楼”等规范名称可显示为用户要求的“标准爆楼”，保留原规则映射，不修改数值门槛或增造细分切点。
3. 九维之后分析原作证据、推算与叠法；最高/扒下限的替代取材、条件主档和争议放在此处，不与默认常态答案或常态九维表并列。三模式仍须独立审查。
4. 用户明确要求最高、扒下限或三模式并列表时按指定覆盖默认呈现。总档不是全属性同档；各维度仍独立取证。合理暂估的条件不能被简洁标题隐藏，也不能为了填档编造证据。

每行首先给**明确主判**：如“弱爆街（科技多束累计，估算）”“普通人级（肉身）”。“断臂击飞成人”“热毁小山”属于依据，不是最终评级。合理假设支持的档名可以作为暂定主档，假设在叠法列披露；纯能量参考要明确被评的是累计能量而非同范围毁伤。不得为满足爆×字样而把智力/经验硬变成能量档，也不得省略尺度、材质或慢释放条件。确实只有普通人档证据就明确普通人，不能编出爆砖。

## 必列九项

| 属性 | 应回答的问题与评定口径 |
|---|---|
| 输出 | 单发/一套攻击可对目标施加的有效输出；分徒手、招式、装备。汪吧档名与J/作用机制分列，累计/持续输出注明时间与攻击次数 |
| 体防 | 身体实际承受何种攻击、如何命中、有何伤；皮肤/内部、装甲、护盾、规避/转移和抗性分开，未命中不能记硬扛 |
| 智力 | 学习、记忆、推理、计算、知识与研发；区分本人、AI、道具或权限辅助。不伪造IQ，等级描述跟实际事例 |
| 战斗智商 | 临战判断、识破、试探、骗招、适应、资源及距离管理；用具体战况支持，不由科研智力自动继承 |
| 经验 | 训练、实战、对手类型、战争/团队经历与能力熟练度；寿命不等于有效实战时间，他人经验不因服从/同称号转移 |
| 特殊技能 | 能力种类、效果、对象、自身表现内影响上限、原世界观最强角色已达档、作用域、发动条件、抵抗/失效；按[双上限规则](hax-ceiling.md)评级。再生与特殊抗性可在此加子项。传送/抹除作用域不是同档拳力 |
| 破坏 | 实际环境破坏的材料、几何范围、终态及时间；按用户要求与输出单列，不能以总能量自动补出覆盖面积 |
| 速度 | 分地面/飞行移动、反应、战斗、攻击传播、载具旅行、传送/跃迁；每一子项采用其适用速度口径 |
| 体量 | 尺寸质量、生命/器官构造、承伤总量/血条；游戏HP与现实人体分开；本体、分身、投影和世界观范围分开，不直接换J |

常用补充项：**力量、控制力、耐力/续航、射程、弱点**。力量区分举托/拉扯/角力与打击能量；控制力看精度、分配/集中、多目标与误伤。恢复、抗性、装备及常用战术在相关时展开，不为凑栏目发明结论。

特殊规则一次作用确实造成有效杀伤时，在“输出”行明确列机制子项及已证对象档／条件，不因缺焦耳就略去其战斗效果；同时保留能量AP、体防和抗性边界。控制、转化、删除成功不自动复制目标的全部输出或体防，也不换算出同档焦耳；仍按 [双上限规则](hax-ceiling.md) 审查。内部可用 [四表模板](../assets/templates/novel-evidence-card.md) 汇总原文、能力和交战，不能用长表替代用户要的九项主判卡。

体量/动物/游戏资料逐字段保留 `value_status:known|unknown|not_applicable|actual_zero`、`basis:measured|documented|estimated|assumed`、数值与单位/区间、原出处、审核日期及适用的物种/性别/年龄/状态。`actual_zero`必须是有证据的0；未查到、工具不支持和不适用都不能填0。体型、器官/组织、受击部位、群体可接触人数与游戏HP分开记录；质量或HP更多不自动等于每一部位更硬。按需将字段原样入research索引，不用一个总分压掉适用条件。

## 聊天默认表格与内部三模式

```text
角色（版本）量级：具体常态主档
必要的暂定/配置说明；统一评定时点与汪吧规则版本
属性 | 常态评定 | 原作出处 | 叠法或推算依据
九维之后：证据与推算分析；最高、扒下限只在这里展开
```

- 必列九项各有一行；速度等必要时加子行。默认采用上述常态表。只有用户明确要求三模式并列时，使用“属性|常态|最高|扒下限|出处|叠法”；内部三模式审计表可保留于工作文件或附录，不能直接冒充默认聊天卡。没有新差异可写“同常态”，不为三个模式强造三套数值。
- 本人、常备装备、可选装备/科技、独立外援分别标归属。模式是证据取舍，不允许在同一行无提示把常态舰炮改成扒下限裸体，再把最高盟友防御当本人输出。
- 小说逐项标明“结尾直证／向前最近补证／延续推定／历史地板”，按[倒序协议](novel-ending-state.md)保留最近取证位置和更晚是否出现升级/替换。旧攻击地板不能叫结局最高，旧弱态不能直接叫结局扒下限。
- 每行至少有稳定原作位置、可点击出处和能复述的传播链；同源可用链接式S1等索引，所指条目须有原作章/集/时间码及访问状态。写“某人强所以同档”不够，需保留属性、状态、实际出力及是否机制克制。
- 有直接表现就写“直接表现”；需要模型时给主估档与关键假设；缺参数优先给有依据的保守估计、定性战果或条件区间。确实未证则说明具体缺口，不省略整行。
- 输出与体防等适用的项目用已核汪吧量级。未发现统一标准的智力、战斗智商、经验，用明确的能力等级/实绩描述，注明不是汪吧统一数值档。速度、体量保留适用物理单位；不能把九项全部硬塞爆砖至论外。
- 先给主判，最高条件统合/跨篇桥接列条件；没有无限构造就不凭“无数”直跳论外。论外适用时仍给逐步构造与原生能力桥接。
