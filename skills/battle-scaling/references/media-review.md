# 媒体审片与返工铁律

制作视频、海报或一图流前必须读本页。这里规定实际审图/审片，不是评级准入、数学验收、程序回执或要求用户填表。脚本只检查时长、显式排除和编排，不会识别精彩、脸部或隐藏切镜。S档、官方来源、字段齐全和导出成功均不能代替审片。

无论使用随包Studio、外部剪辑项目还是临时FFmpeg脚本，本页都适用，不能因换工具跳过。

## 先锁定本次媒体内容

只执行用户要求的媒体类型、人物配置、文字和样式。海报默认内容为双方名字、必要版本短注、中央VS、所选分界及小Battle Scaling水印；背景和排版服务这些内容。未要求的量级标牌、胜负结论、战术说明、口号、额外人物、梗图、额外署名和装饰性文字不得自行加入。海报不混入一图流的求饶贴图与配文。用户指定的扩展内容优先，既有默认模板无需逐次询问。

## 审片顺序：源区间 → 真实用途 → 最终成片

1. **完整看候选。** 正常速度看完整个拟用区间，确认谁是主体、在做什么、精彩发生在哪里，找等待/空镜/其他人物独立镜头、字幕角标和内部切镜；再看入出点前后。中间一张好截图不能认证整个区间。
2. **沿镜头重划入出点。** 有内部切镜就拆成独立镜头候选。长展示可按模板拼接；维度对照底板与单项揭晓只能用单个连续镜头，不能直接塞已经剪好的混剪。`continuous:true`指确实没有内部切镜，不指“在一个文件里”；预拼接文件写false，只供合适的长展示。
3. **在真实版式看。** 分屏、单人竖幅、海报、片尾分别审，不能相互代验。实际套用cover/contain、焦点、文字/VS、缩放、旋转及转场，看最大放大、最靠边的位置和主要识别窗口。竖图居中铺满横向半屏尤其容易丢掉眼睛。逐素材调焦点、缩放、补背景或换图，不把所有角色统一居顶。
4. **看真正导出的文件。** 先正常速度通看，再逐段看所有维度对照、双方揭晓、换镜/循环接缝、变速接点及片尾。快切要看上段末尾、当前全部与下段开头；同底板的文字/特效变体也要覆盖，不只抽中间代表帧。问题只改对应内容与接点，不重评角色或重抽模板。

用宿主播放器、视频视觉工具或FFmpeg即可。不能直接连续读视频时，输出短预览和密集连续帧：极短维度素材完整逐帧展开，成片每个切点看相邻数帧及干净识别窗口。长段稀疏联系表只能定位，不能证明没有短暂异镜。场景检测仅提示疑点，光闪会误报、细微切镜会漏报。缺视觉能力就交待审预览/工程并说明未完成视觉复核，不能默认通过；听觉受限同样如实说明。

审看时先不靠文字猜人：对照底板两方、揭晓单方都应从画面本身可辨。短槽位按帧看全区间，尤其第一帧与最后一帧；一帧错人也需返工。联系表格子若小到看不清面部，打开原帧或放大，不能为塞进一页将竖屏缩成百像素小图后宣布已审好。模板过渡造成的模糊与源素材夹带另一个机位分别处理，不能因都有“闪一下”就混为一谈。

## 不通过即返工

| 检查项 | 必须返工的情况 | 处理方式 |
|---|---|---|
| 比较底板构图 | 眼睛、面罩或主要识别部位出画/贴边，只剩下巴或躯干；文字/VS遮住唯一特征；动效后才裁掉 | 按实际半屏调焦点和缩放，给旋转/放大留余量；不足换清楚头肩图/片段。揭晓清楚不能豁免底板 |
| 单项揭晓辨识 | 只能看见光雾、粒子、暗部或模糊颜色，不能迅速认出胜者 | 按[即时辨识硬门槛](media-selection.md#维度揭晓的即时辨识硬门槛)排除并换镜头，S档也不豁免 |
| 两种快切短槽位 | 有源片内部切镜、原片转场或闪入第二机位/其他人/另一场景；不足时自动回卷 | 裁到单个连续镜头内部并留少量边界余量，覆盖完整槽位和转场实际取样。太短就换更长单镜头或稳定图片，不能在槽位内拼第二镜头、循环或硬慢放凑长。两个机位都是同一角色也不算单镜头 |
| 长展示精彩度 | 等待、空镜、无兑现的冗长蓄势、主体太小/糊；只是够长、高清而不精彩 | 优先有持续动作、气势或清楚人物表演的精彩长段，其次几个精彩原速短段；平静、微笑或凝视也可精彩，不强迫人人咆哮。“长且连续”不是精彩理由 |
| 不必要慢放 | 原速好素材仍可用却降速填长，短揭晓拖沓，低于0.5倍或预先慢放后再降速 | 默认原速。原速优质素材合理补搜仍不够且慢放后观感成立，才对所选长展示显式允许，最低0.5倍。原生慢镜或作者明确要求可保留；烘焙慢放须说明，不能伪称原速绕过规则 |
| 海报/一图流内容 | 未要求的内容、错版本/装备/名字、额外人物、徽标挡脸、透明模板硬边；求饶图贴错位置 | 对照本次内容边界删改，原尺寸和手机缩略图都看。只保留用户要求的有意遮挡，不能以“有创意”豁免误加内容 |

脸不是唯一识别锚：非人角色可用清楚核心、轮廓和装备；人脸/面甲近景则须保住用于辨识的部分与边距。长展示允许有意局部特写和多镜头蒙太奇，不把短揭晓门槛扩大成“全片每帧必须露脸”。保留模板设计的短过渡，但素材内部不能再藏第二次切换造成异镜闪现。

一图流的水龙求饶图属于有意遮脸：有脸优先刚好铺满脸，无脸才贴核心，按实际大小和朝向缩放／旋转。贴太小、贴错部位、只凭默认框定位或盖住大片身体，须调整后再交付。

**任一上述问题未消除，该用途即未通过，不能作为“已审好成片”交付。** 修对应素材/构图后重看该段及接点；不能只降为C档继续塞、写免责、勾通过、换文件名，或让用户代为发现。缺素材沿既有优先级退到清楚图片/动效，已知不清楚或夹异镜的快切片段不能作兜底。

交付只需短说明实际改动与观看限制，不默认生成验收证书、分数表、哈希或冗长报告。软件测试通过与作品好看是两件事。

## 可直接采用的看帧方法

先建好输出目录。以下只是定位/看帧，不自动判合格；时间、帧号与比例按实际素材改。

```sh
# 将拟用的0.8秒短镜头全部展开，不每隔数帧抽样；帧序列供视觉查看
ffmpeg -ss 12.3 -i source.mp4 -t 0.8 -an -vf "scale=320:-2" -fps_mode passthrough review/frames/%04d.png
# 看导出文件在指定切点附近的连续帧，含上一段、切点和下一段
ffmpeg -i final.mp4 -an -vf "select='between(n,615,627)',scale=540:-2" -fps_mode passthrough review/cut/%04d.png
```

把连续帧做成按序标号的联系表，查看全部格子；面部太小就增大缩略图或单独打开。源素材需要首尾各留少量已核的同镜头余量，不能把前一个/后一个机位混进有效区间。先在最终画幅做短预览确认裁切，再导出完整视频；改焦点、缩放、动效或入出点后复看受影响画面。

Studio工程可在导出后运行以下专用审看工具。它读取真实`compiled.json`和最终MP4，把每个compare/reveal完整逐帧展开、包含接点相邻帧，生成可点开放大的HTML；不是自动验收，也不改工程或成片：

```sh
node scripts/review-video.mjs --job 工程ID --final final.mp4 --out review-new
```

命令在Battle Video Studio根目录运行，使用FFmpeg。它不生成“合格”分数、不写S档或审核回执；宿主需实际看每段与异常帧，长展示继续正常速度通看。没有工程时用本页FFmpeg方法对最终文件做相同审看。素材已预裁/变速/换名，仍保留原片`sourceId/sourceIn/sourceOut`，从原片区间判断复用；优先原始宽画幅按真实用途裁一次，避免先竖裁再横裁使脸部永久丢失。对不同用途只一个`cropUsable:true`不代表各版式都适合。
