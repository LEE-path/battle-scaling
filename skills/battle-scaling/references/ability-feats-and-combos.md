# 末期能力、实际表现与组合打法

角色定级与VS的前置工作是：**查全所评末期配置的能力、有效设定及实际表现，再分析组合打法**。技能名称和未经核验的简介只作检索入口；已核原作能力定义、可靠旁白及作者设定可按[证据协议](evidence.md)支持明示事实和有据上推，同时主动查成功、失败与对抗。没有实演不能包装成已发生，但也不能把可靠设定降为只能检索、不能采用。下述流程适用于[统一综合评级](modes-scaling.md)及两种PK呈现。高光、通常和低谷表现均作证据与交手条件参考，不再分别生成角色档位；标准和特能双上限不变。

## 先判断档案是否足以复用

未做过完整评级的小说角色，或虽有旧评级却缺完整能力与表现档案，优先使用 [完整论战拆书项目](novel-refpack-pipeline.md) 建档后再定级、对战。先核已有档案的原文身份、版本、覆盖、阅读回执及宿主验收，不能因有一篇报告、几章笔记或九维表就认定完成。

合格档案至少包括：所选作品范围的实际阅读覆盖；同一末期时点的能力取得／升级／保留／丧失时间线；逐能力正反表现与可回溯原文；九属性依据；状态及配置继承；关键交锋、抗性、限制、矛盾与剩余缺口。全书任务覆盖和宿主语义审查分别记录，程序`complete`不认证理解，也不能保证绝无遗漏。综合版本逐作品核范围及桥，不以一部的档案冒充全系列完成。

没有合格档案时主动取得可核原文，执行`prepare → tasks → 实际阅读 → accept → build/verify → 宿主末期档案审查`。阅读任务从结尾向前组织并扩展至所需全书覆盖；找到一条高表现或某个著名技能不提前收工。网页逐章查询和轻量`novel`用于发现原文、补缺章、核版本／引用及补证，不能代替首次完整拆书。

完整原文确实无法取得时，继续查可访问版本并保存已读范围、阻断及待办；可交付有明确范围的暂定档、已证地板或条件对战分析，但不称完整评级／完整建档，也不把材料缺失当能力不存在或数值为零。用户只问局部机制、已有合格档案需补一条引用时，允许定向核查，不为局部问答强制重拆全书。

## 每项能力都要查实际表现

按原作术语、别名、取得来源与相关对象归并能力；主动／被动、装备授予／自身持有、临时／永久分开。逐项记录：

|项目|需要查清|
|---|---|
|末期归属|何时获得、升级、被复制／授予、丧失或恢复；末期还能否独立发动与维持，需什么配置或资源|
|实际成功|对谁、什么类型及状态的对象做了什么；对象的具体受作用部分、范围、数量、持续和实际结果；原文章／页／时间戳|
|发动过程|感知、理解、定位、接触、媒介、准备、发动耗时、命中和生效顺序；代价、消耗、次数、外援及疲劳战意|
|对抗表现|实际突破或未能突破何种防御、抗性、屏蔽、恢复或权限；只对特定机制有效还是有可继承证据|
|失败与例外|失效、被反制、对象不适用、无法读取或操作、能力中断；保留当次状态，不以早期失败直接封顶末期|
|证据性质|实际动作／结果、旁白／作者或角色声明、理论计划、合理推断分开；“当次做到”“全力／上限已证”“待核”分开|

能力的读取、复制、剪切、剥夺、删除、转移与在新载体上生效分别取证。控制一具身体不等于控制全部分身；复制成功不自动剥夺原对象；杀死对手不自动获得其能力。只看见外观或效果不等于读到机制本体；同样，不因没有再次演示就判永久技能已丧失。

末期档案将每项能力链接到具体表现ID、反例、有效声明及延续桥。只有可靠设定时保留声明性质与推导，仍可按模式独立支持评定；不能要求先补出同规模物理破坏才承认。尚未查完、已查但没有直接实演及明确反证分别记录。

## 从表现组合成获胜方法

定级和PK前由宿主审查完整配置，主动找能力之间的协同与阻断，不只比较招牌技能、量级标签或最高形容词。每条候选链记录：

`目标 → 察觉／读取 → 定位／接近 → 发动与命中 → 穿过对应防御／抗性 → 实际效果 → 阻止恢复／逃脱 → 胜利条件`

按角色实际能力选择必要环节，不要求每条都走信息读取。逐环绑定原作表现、当时状态、末期继承和前提；**组件有实绩不等于组合已实际完成**。原作出现过的组合与本场合理推演分开，后者说明顺序、时机、资源、配置共存、反制和失败窗口，不把假想战况反写成角色战绩。

把对手的能力机制、载体、发动条件、控制权、资源及支援关联也列为可能目标，而非只打身体或硬抗效果。例如有表现依据时才考虑“读取／定位→复制或剪切→自己取得／对方失去”；这只是候选分析方法，不是所有信息能力都自带的通用胜招。

同样审查对方最强可行胜路及反制。特殊能力继续逐目标绑定`hax_checks/hax_requirements`，分别检查自身已证影响上限、原世界最强角色已达天花板、对象兼容、发动和抗性。没有记录不等于没有抗性；“绝对”“作者”“主角”不填补缺环；已知超限不能由组合、激进解释或假设绕过。

## 查漏、更新与交付

优先补会改变胜负的缺口，区分“本角色是否已有这项本领／实绩”与“跨作品能否对目标生效”。前者未查清就继续拆书或回原文，不能笼统用跨作品不确定性遮盖漏查；后者保留真实未决条件，不以原作没有直接跨作交战为由放弃合理推演。

发现任一缺项，主动按[缺口补链](evidence-gap-recovery.md)寻找相关对象、共同参照与替代模型，核机制、部位、出力和状态后尝试补齐。信息暂缺不等于能力不存在；没有同款组合或交锋镜头也不等于只能请用户新设定。现有证据确实不相容或尚不足时如实保留缺口，不用循环叠加和材质名排序硬填。

新增关键能力、实绩、反例或配置变化后，重评双方获胜路线、先手、生效、抗性、恢复与翻转条件，再更新主判；不能只往旧结论后添一句技能。已证、条件可行、合理倾向及严格未决分开，仍按现有[判胜协议](matchups.md)和双上限审查处理，不新建绕过审查的“已胜”结论。

使用[小说四表模板](../assets/templates/novel-evidence-card.md)保存能力实绩与组合链；原文进入`CASE.sources/feat_reviews`等现有字段，组合进入`matchup.win_paths/requirements`。工具只核结构、引用及声明的覆盖；宿主负责查证语义和档案验收。不要求聊天展示全部工作表。
