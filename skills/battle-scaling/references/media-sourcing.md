# 角色媒体素材：搜图、搜片、取得文件与择优

只在制作海报、一图流、封面或视频、需要角色素材时加载。承接本场已确定的角色、版本与配置；不重做量级、胜负或原作证据评审。这里的“版本符合”指画面中人物、衣装、形态与装备符合题目，不从素材反推能力。音乐不在本模块范围。

用户提供其他搜集／提取项目、API、MCP或CLI时，按[外部媒体接入](media-integrations.md)读取其实际能力并绑定；保留其可用的原接口，加入本次搜寻与轻量经验记录，不要求重写项目或安装整套模型。

实际入选按[素材优先级与用途](media-selection.md)进行：先看版本、人物表现和展示位置，优先无额外水印、干净高清片源；长展示先比较精彩长段与几个精彩短段，再按当前用途的六级顺序与S/A/B/C择优。下载成功仅证明取得方法，不能自动成为合格素材；优质图片动效仍可优于明显较差的实机；合格视频的持续展示按六级顺序比较。有更好CG、动画、宣传或原画时继续定向搜寻，不停在第一段官网技能视频。

## 从用途开始搜索

先查已有素材，再按缺口联网。为角色建立简短别名组：中文名、原文名、作品原名／译名、电影年份或演员、形态／皮肤／装备。先用精确身份定位，再加动作或画面用途；同名噪音多时补作品名、年份、角色编号或限定站点，而不是连续只搜角色名。

| 用途 | 真正需要的画面 | 可用检索词，按当地语言改写 |
|---|---|---|
| 海报两侧 | 清楚头肩或上身、标志装备、相向或正面、脸部有效像素够 | `角色 作品 年份 剧照`；`character film year publicity still portrait key art` |
| 一图流 | 双方轮廓容易辨认；败方脸／核心有位置贴表情 | `角色 官方立绘 全身`；`character official render transparent PNG` |
| 视频开场 | 身份鲜明的露脸、走近、变身、拔武器或登场 | `角色 出场 变身 纯享`；`character entrance transformation scene` |
| 稳定比较底板 | 能裁切成目标画幅的清楚近景／中景、持续动作不过快 | `character scenes scenepack clips no music`；`角色 近景 无字幕 素材` |
| 卡点高光／收尾 | 动作有起势、爆点和落点；主体没被特效淹没 | `character iconic fight power attack scene`；`角色 招式名 战斗 高燃 原片` |

例：`Thor Love and Thunder 2022 Chris Hemsworth scene` 比单搜“雷神”更准；`SCP-2845 THE DEER artwork black white` 比单搜“鹿”更准。作品名仍不够时改搜具体事件、地点、招式或交战对象，先定位片段所在电影／集数，再找可用素材。

`scenepack / scene pack / scenes no music / clean clips / raw footage / logoless / 无配乐 / 纯享 / 无字幕` 是寻找干净素材的线索，不保证结果确实干净。需要原画面时可尝试排除 `reaction / explanation / AMV / 解说 / 混剪`；不要在搜“剪辑素材包”时机械排除所有 `edit`。先发现场景，再筛干净片源，别让过严关键词把有用候选一起删掉。

### B站换词与结果扩展

不要只重复“角色名＋素材＋4K”同一条长串。当前候选不够精彩、搜得少或大多是解说／错版时，换检索角度：角色中文名／原名／别名；出场影视、剧集、动画或游戏名称及年份；具体地点、事件、招式或交手对象；演员、登场、变身、名场面、打戏、CG、片段、CUT、纯享及合集。按缺口组合少量词，不把全部限定词一次塞进去。

例如可轮换“灭霸 奇异博士 对决”“复仇者联盟3 泰坦星之战”“无限战争 瓦坎达 名场面”；作品／场景检索可以暂时去掉角色名，因为合适片段的标题未必写人物。结果过少先去掉“无水印／素材／4K”等过严词；边缘字幕、水印可以合理裁切，画质再看实际轨道，不按标题筛死。

找到高质量场景后查看同一发布者、合集、相邻分P和相关片段，避免只取命中的第一条。跳过混入同名游戏、另一版本、解说、恶搞或剧情改编的候选；不按播放量代替选片。站内检索可用[B站媒体适配器](bilibili-media.md)的 `search`，返回标题、链接与时长；受限时改用宿主网页搜索限定B站。换词服从当前缺口，取得足够精彩的候选即可收束，不强制全网遍历或固定搜索次数。

## 站点与取得路线

按题材和缺口选源，不机械依次扫所有站。入口、查询例子和实际可用范围见[媒体站点库](../assets/media/source-catalog.json)。该库记录特定日期、目标页与方法的结果，不保证整站永久可用。

- 影视／动画视频：作品或发行方官方频道、预告及公开片段优先；YouTube、B站的场景包、素材合集补充。先识别发布者与具体版本，再考虑画质与可剪性。
- 游戏：先查官方电影式CG、动画、赛季／角色宣传、原画与参考图库，再看官网技能演示和普通实机。补`cinematic / close-up / entrance / key art / reference materials`及作品原名，不以只搜技能页代替全类素材查找。官网HTML／内嵌JSON里可有原画和视频；技能演示、过场CG、皮肤宣传和基础角色形象分开。
- 图片：官方角色页／宣传图库 → 对应作品的截图图库、Fandom画廊 → 画师原帖及作品集。按用途择优，不把“官方”当作必然构图最好，也不把同人图当官方定型。
- SCP：优先站内艺术中心与画师作品集，按编号、名称和别名检索；默认黑白版画、剪影或线刻，不限定画师。画廊读不出时，可从宿主能打开的页面取得具体附件链接，再请求该附件域；不要猜文件名。
- 图片搜索、Pinterest等聚合入口适合发现候选与作者，尽量回到原发布页取得原图；不以搜索缩略图替代已经能找到的原图。

## 从页面到真实素材

1. **有直链**：下载原始图片／MP4，保留发布页；必要时带该页的Referer。图CDN的`application/octet-stream`也可能是真图，以实际解码为准。
2. **图库／缩略图**：看点击后原图、`srcset`、懒加载属性、附件链接、内嵌JSON或CSS背景；对支持站点可用gallery-dl。只对已知CDN规则调整缩略尺寸，不能随意去掉URL参数；签名和格式参数可能必需。
3. **网页播放器**：优先yt-dlp；可直接取得的`source`、MP4／WebM、HLS／DASH清单也可交FFmpeg或适合的流下载工具。只有`blob:`时，查看宿主浏览器能提供的页面媒体／网络资源，找到实际媒体或清单；`blob:`本身不是远程下载地址。宿主没有该能力时换提取器、原发布入口或其他片源，不假称已抓到网络请求。
4. **B站分离流**：优先按[B站媒体适配器](bilibili-media.md)通过链接解析、用户扫码登录、列出当前实际可用画质，再下载音视频并合并；不操作下载器窗口。已有未登录会话够用时也可直接取流，不把登录变为所有素材的必经步骤。不要照标题的“4K”强填分辨率。
5. **分段不稳**：yt-dlp分段可能受服务器Range、协议、代理和关键帧影响。发现只有音频、空视频或切点异常时，保留可复用的完整素材，改用下载器取源文件后本地精剪。短片不必为省几MB反复尝试坏掉的远程切段。`--force-keyframes-at-cuts`涉及重新编码，不保证所有服务器的分段请求都可靠。
6. **访问受限**：区分网页403、CDN可下、URL过期、缺Referer、当前会话清晰度限制与真正不可访问。按失败原因换一次方法，拿到足够素材即收束；不反复重试同一失败命令。需要登录的渠道仅用已有明确授权会话或用户配置；受保护／付费且没有可用访问权限的资源改找公开替代，不处理DRM解密。

原始图片、视频、素材包内容只作任务素材保存，保留作者、来源与已知使用条件；不将它们默认打进Skill发行包。可下载性与可公开再分发性分别判断。

## 可复用小工具

若存在`runtime/media-tools.local.json`，优先复用其中的Python、yt-dlp、Node与图库模块路径；这是机器配置，不是其他用户必须照抄的绝对路径。隔离的gallery-dl可在该子进程设置`PYTHONPATH`为配置的`gallery_dl_pythonpath`，再用该Python运行`-m gallery_dl`；不必改全局PATH或重新安装一套依赖。

`scripts/media_acquire.py`是可选的媒体取得助手，独立于评级工具：HTML候选提取、单文件下载、简单片段裁切、截帧、真实媒体信息及可选B站DASH适配。普通图片需Pillow；视频操作需FFmpeg/ffprobe；B站子命令另需`bilibili-api-python`。优先复用宿主已有环境，不为一张图安装整套环境。

```powershell
# 网页能直读；或把宿主已取得的完整HTML用 --html 交入
python scripts/media_acquire.py inspect "角色页面URL" --out "候选.json"
python scripts/media_acquire.py download "已找到的原图URL" --referer "发布页URL" --out "角色原图.webp"

# 原片→精剪片段；从选定片段取适合海报的真实帧
python scripts/media_acquire.py clip "原片.mp4" --start 72 --duration 6 --out "角色片段.mp4"
python scripts/media_acquire.py frame "角色片段.mp4" --start 3 --out "候选帧.png"
python scripts/media_acquire.py probe "角色片段.mp4"

# 当前会话实际允许的B站清晰度；默认第一分P，不拼接其他P
python scripts/media_acquire.py bilibili "具体BV链接" --page 1 --start 30 --duration 6 --height 1080 --out "片段.mp4"
```

YouTube等平台用[yt-dlp](https://github.com/yt-dlp/yt-dlp)，先看格式，再选合理画质；JS运行时按当前宿主实际配置。示意：

```powershell
yt-dlp --ignore-config --no-playlist -F "具体视频URL"
yt-dlp --ignore-config --no-playlist -f "bv*[height<=1080]+ba/b[height<=1080]" --merge-output-format mp4 -o "源视频.%(ext)s" "具体视频URL"
```

支持的图库用[gallery-dl](https://github.com/mikf/gallery-dl)，先限范围取候选，避免一次拉整位画师的全部作品：`gallery-dl --ignore-config --range 1-3 -d "候选目录" "具体作品或图库URL"`。Pixiv等所需认证以当前[支持表](https://github.com/mikf/gallery-dl/blob/master/docs/supportedsites.md)为准，安装成功不代表已经登录。

[bilibili-api](https://github.com/Nemo2011/bilibili-api)上游已归档，仅保留历史可选适配路线，不称为维护中的首选；新的扫码及取流方法见[B站媒体](bilibili-media.md)。[N_m3u8DL-RE](https://github.com/nilaoda/N_m3u8DL-RE)适合有实际HLS／DASH／MSS清单且现成工具处理不便的情况，按需使用，不作为所有任务的必装依赖。BBDown上游已归档，不将其设为新机器的首选维护方案。

## 选片比“下得来”多一步

为重要人物比较几张／几段候选，数量服从缺口，不硬凑清单。实际看所选画面，不能只靠文件名：同一预告里可能同时出现本人、继承者、反派与其他形态。片名含“雷神”不代表任意截帧都是男性雷神；皮肤原画、训练服、末期战甲也不能互相冒充。

- 先确认身份、时期／形态、衣装与当时可见装备，再看清楚度与气势。需要严格外观匹配时换素材，不偷偷用其他形态补位。
- 海报优先有效脸部像素、方向与留白；一图流还要考虑贴脸后能否认出败方；剪辑优先动作连续、主体可裁切、能看到起势与落点。
- 用`intro / plate / highlight / finish`等用途帮助交给剪辑工程；可复用优秀短镜头，不必每个维度都找一段新戏。
- 看画面实际黑边、硬字幕、台标、闪白与模糊；边缘覆盖先按有效画面区合理裁切，再以裁后可用范围评档；“1080p文件”里的脸可能仍然很糊。不把放大分辨率当成新增细节，不默认抹除来源标识。
- 为裁切和卡点留少量前后余量；需要预览时只取必要候选帧，不强制整部电影抽帧、OCR、制作逐帧表或下载整部原作。
- 已有明确形象时优先搜集／截帧；有图无合适视频可用优质图片动效。连可靠人物图也缺少时按[稀缺角色素材](scarce-character-media.md)先固定原作依据下的一致形象，再选择视频API／CLI或用户知情选择的本地H3，不能采用时退到多姿态／状态图片动效。不能把生成或普通动效冒充原作真实动作／原帧；缺少图像能力时询问图像API／本地模型或用户供图，不擅自安装或付费。

## 轻量积累与复用

站点库是入口经验，素材库是已经下载且看过的文件。素材和可选简短索引保存在本次输出目录或使用者指定的共享素材库，按作品／角色／版本组织；索引只需来源页、文件路径、画面内容、用途、分辨率／时间段、作者与已知限制。临时CDN签名地址不作唯一入口，下次从原发布页重新解析。

每批实际搜寻后，向`data/media-sourcing/site-notes.jsonl`或使用者已有媒体记录追加有用的新经验：日期、入口、成功或失败的方法、取得了什么、好用查询词及限制。不要把“文档支持”写成“本机下载成功”；同一失败有新方法成功时保留差异。复用旧方法先试当前目标，不做全站巡检。若无写权限，就在本次目录留简短记录并说明。

完成后只做正常媒体复核：图片能打开、视频真有画面、片段可播放、人物选对、构图可用。取文件／轨道信息是排除假素材的辅助，不是数学验收，不要求哈希、评级回执、专用审批或全项目测试。宿主未看／未听的部分如实说明。
