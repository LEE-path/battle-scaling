# 单挑、多人和动物对战

本页用于论战。作者提供人设与能力并要求创作、指定桥段或结局时，改走独立 [战斗写作辅助](writing-battle.md)，无需把作者指定的胜者论证成总体胜率优势方。普通VS仍默认下述宏观／过程格式。

**所有PK先独立定档。** 先逐个执行[独立角色量级评定](character-rating-workflow.md)，固定本场配置并验收主档、九维卡、来源与推导。主档及适用输出／体防／破坏须给具体、有据的综合主判；已证下限随依据保留，不能以局部保底、模糊或未定占位。各方完成后才进入胜路、胜率和过程；缺档时继续单人研究，不用条件PK、五五开或停战替代。顶层`independent_ratings`供共用门检查，缺项返回`needs_independent_rating`。

先锁定标准，默认汪吧。`standard=vsb` 时先读 [VSB对战规则](vsb-combat.md)和[特能规则](vsb-hax.md)，使用已记录的SBA／显式覆盖条件；不把普通离场、瞬间昏迷或一步失能当作已满足SBA时长。宏观胜路与主估需带 `vsb_victory` 条件审查包；Tier0真体对Tier0不生成胜率。

## 两种呈现

默认 `presentation:"overview"`：先写谁更可能赢，再写带依据的胜率主估/合理区间、决定胜负的机制与翻转条件，不主动展示逐步战况。用户明确要求具体战斗过程才选 `presentation:"process"`：内部先完成宏观分析，正文默认展示**优势方获胜的一局完整战斗→总体胜率及理由→另一方的获胜可能与翻盘条件**，附来源及关键假设；具体选局、叙述和未决处理按 [过程协议](combat-process.md#详细打斗的默认输出优势方的一局胜局)。所选单局不能反推总体胜率。`--pk` 可覆盖呈现，评级统一使用 `--mode integrated`；高光、通常、低谷只作为表现和交手条件参考。缺综合过程输入时补建 `mode_processes.integrated`，不自动复用旧模式轨迹或互斥配置，详见[统一综合评级](modes-scaling.md)。

固定双方综合评级、版本/状态、装备、场地、距离、信息、准备时间、行为取向及胜利条件。用户未给条件时自动采用可解释的通常可战方案，并为显著改变结论的条件输出分支；不要反复停下来逐项提问。

独立定档验收后，按 [末期能力与实绩协议](ability-feats-and-combos.md)查全当前配置、能力取得与保留、逐能力成功／失败、发动条件和对抗范围，再分析组合；没有合格完整评级档案的小说角色优先完成[论战拆书建档](novel-refpack-pipeline.md)，不靠零散查章拼出完整配置。既有报告不自动合格；按[完成性协议](rating-completion.md)检查当前修订、候选取舍和撤回状态，有一个具体下限或旧通过标签不等于已完整定档；原文受阻的部分覆盖只能交付部分研究，不能自动取得正式PK或故事准入。

候选胜路不只打身体或硬抗招式：有实绩依据时，也审查读取／夺取／复制对方能力、破坏载体、切断发动条件、资源或控制权。每个环节分别绑定原作表现及末期继承；组件分别有表现不代表组合在原作发生过。区分本角色能力漏查与跨作品作用未决，优先补决定胜负的实际缺口。补到新关键能力、实绩或反例后，重评双方整套胜路与反制并更新主判，不仅在旧结论后附加技能；既有双上限、兼容及抗性审查继续适用。

按每方可行获胜路径分析：察觉/接近→命中或触发→穿过对应防御/抗性→造成失能→在恢复/逃脱前完成胜利。每个环节写证据及条件。特殊能力先执行 [双上限规则](hax-ceiling.md)：默认取自身表现内影响上限，无论高光／低谷视角，均不得超过原世界观最强角色已达到的量级；超过任一道已知上限，本次用法不成立。世界观结构不能代替角色已达量级，世界最强也不自动赋予每个特能同档能力。在上限范围内，继续分别核查作用对象、启动、范围、跨作品兼容、抗性与限制；输出高不自动命中或获胜，施术者的肉身AP不直接限制特能。

区分原作发生的事件与假想对战中的推断。有据但仍含争议的继承可保留为假想战斗条件分支，须显示最小前提集；可靠继承应直接参与综合评级，不以“最高”另档逃避主判。叙述性“模拟战况”只可用于说明已建立的获胜路径，不可回流成新的原作证据。

每次裁决同时提出反方最强可行获胜路径：对照同一版本/开局，检查先手、发动、命中、抗性、资源、恢复与胜利窗口；把翻转主判所需的最少条件和相反证据写清。可按既有win_paths为双方建路径，不把“总有一招能赢”当已证，也不因需要反方论证就编造成功路线。装备、授予、召唤、融合与外援归属及敌手实战资料按 [交锋档案](discovery-dossiers.md) 回原作核对；不用固定类别优先级、权重或被秒降档代替逐项判断。

多人记录每队成员、数量、同时接触人数、地形瓶颈、协同、视野、战术、成员退出和体力消耗。不把十名个体的AP相加为一次十倍攻击。若原作明确合击/能量融合，才单独建立合击模型和证据。

动物任务确定物种（鬣狗有多种）、性别、年龄、代表性健康个体/极端个体、体重区间、地形与是否允许撤退。测量、模型估计和网络传闻分开。咬合力N、接触压力Pa与身体伤害机制分开。采用动物园/物种机构/原始生物力学和行为论文，不能把影视或“能举自身多少倍”传言当测量。缺真实群战校准时给优势及条件分支，不输出伪精确胜率。

case.matchup = {teams:[...], conditions:{...}, win_paths:[...] }，顶层另带已验收的`independent_ratings`。每条win_path含id、winner、evidence_ids、requirements（各含claim/status/evidence_ids）、unresolved_counters。脚本只能审计宿主声明supported的环节，不能替宿主理解战术。双方已有具体定档时，双方路径都成立可标contested；交互仍有条件时标insufficient_evidence并给有条件结论。**角色定档未完成则返回独立研究，不适用本段继续PK的规则。**

验收案例：死星毁星与卢克击中设计弱点必须分开；SCP-3812自动防御与肉身硬度分开；银背大猩猩vs十只鬣狗给物种/体型/行为分支和逐项获胜条件。翻转双方输入顺序后，证据和结论应保持对应一致。

新 `win_paths` 默认用于综合判断，需限制时可带 `modes:["integrated"]`。`--mode integrated` 生成综合 `matchups.integrated`；旧模式结果仅作历史读取，不能重命名为综合完成。没有完整演绎支持时仍应主动给合理推断：在`matchup.mode_assessments.integrated`填写包含`winner`、`status:reasoned_estimate|conditional|undetermined`、`reasoning`、`evidence_ids`、`critical_assumptions`的对象。该综合判断进入报告，条件分支保留各自依据；工具检验引用及读取状态，不把宿主机制推断升级为真实对战统计。不能仅因路径审核为insufficient_evidence就停止给最可能结果，也不能把宿主写下的winner称为已获实验验证。

宏观胜率可附 `win_estimate`，明确性质并采用与证据强度相称的粗粒度；不因可填写小数而报伪精确百分比。示例：

```json
{
  "method":"reasoned_estimate",
  "basis":"A的先手与破防路径较稳定，但B仍有发动封印的窗口。",
  "evidence_ids":["s-speed","s-attack","s-seal"],
  "assumptions":["跨作品能力可作用于对方；未知准备时间按双方无准备"],
  "outcomes":[
    {"outcome":"A","min":0.6,"best":0.7,"max":0.8},
    {"outcome":"B","min":0.2,"best":0.3,"max":0.4}
  ]
}
```

这是格式演示，不是实测统计。结果类别须互斥且涵盖所讨论的结果空间，主估合计1；有互杀、平局或未决时单列，不能硬把双方胜率互补。各区间只是判断不确定范围，不是统计置信区间。不可用“模拟了十条分支，A赢七条”得出70%；分支没有已知概率分布。工具只检查数值一致性、来源ID与读取元数据，宿主负责查证语义、分析机制和解释权重。来源不可读或判断未定时工具撤回数字。没有合理依据时保留有条件倾向，不编造一组数。

若特能检查只有显式机制假设下成立，综合主判和内嵌win_estimate都标为conditional，数字对象保留继承的assumptions与hax_review；聊天表述为条件分支胜率，不能只复制数字而丢失前提。

特殊能力交互用候选关系表组织：`能力归属与配置/目标对象与状态/自身已证影响上限/原世界观最强角色已达档/目标档与比较依据/发动与范围/命中条件/防御与抗性/兼容桥接/证据/反例/结论`。同名能力、同档名或“概念/时间/现实”字样不能代替这张表。脑内行动意图、裁决、状态更新、叙述分开；未知能力/速度不填零。

每条特能路径及依赖它的 `requirements`、`mode_assessments[mode]` 或 `win_estimate` 标记 `is_hax:true`，绑定 `hax_requirements:["检查ID"]`；同一主估依赖的全部特能检查都要绑定。检查集中在 `CASE.hax_checks`，具体格式见 [证据包](case-format.md)。已知超限路径标为blocked；缺关键比较的路径不能升为supported。受阻或未定的主估撤回winner和数字，不据此自动判另一方赢；独立成立的物理路径可继续采用。未标记的旧包列为未审，不能宣称特能规则已经覆盖。
