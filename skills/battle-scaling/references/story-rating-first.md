# 故事版：实际独立评级完成后才进入写作

本页是共用独立评级到写作的交接说明。研究入口在[共用独立流程](character-rating-workflow.md)；单独评级和故事来源的请求均交同一种[单人研究任务](character-rating-worker.md)，先实际使用搜索、阅读与推理工具，得到可独立交付的报告。写作参考和优秀范例留到交接完成后加载。`writing_battle.py`负责后续写作组织，`rating_preflight.py`负责声明准入；二者都不会替宿主搜索原作、发现漏掉的战绩或完成叠链。

旧`normal/highest/lowball`独立包只作历史材料：先补核完整对象、重要外层关系、候选取舍和当前配置，再生成`mode:integrated`的新验收行；不能仅改标签或沿用旧通过结论。已核且未变化的原文、能力档案、计算及依赖校验可以复用，避免无差别重做。

## 评级内容的优先级与语义验收

故事前置的每份角色报告，应能直接回答同配置下的独立量级请求。研究和创作分阶段投入：决定主档、重要属性或胜路的证据尚未处理时，先补研究，不以赶正文、减少工具往返或让情节顺畅为由提前收束。充分后按既有停止条件进入文学创作；不以重复校验、无限扩搜或更长日志表示严谨。

宿主须实际读关键来源并复演下列推导；复用既有报告和记录即可，不增加专用回执、表格或固定数量要求：

- **具体档位如何得出。** 主档、重要输出／体防／破坏及速度，须能追溯到“原文命题或测量 → 对象与关系 → 可传属性及条件 → 适用规则／参照 → 为什么选这一具体档”。缺J可按可靠设定、结构、比较关系作合理主估；“很强、远超建筑、打过神战、城里交战”不能单独证明某个国／城档，“发生在天上”也不证明某个速度档。`basis:estimate`、语义估档或低置信标签只说明结论性质，不能补上缺失的关系与映射。
- **较高候选实际审到哪一步。** 主动查参照角色、装备及招式的有效实绩、设定、反证和当前配置继承。对波、破防、最强／同级设定、结构性作用和非伤害能力均可形成重要上推；不等用户指出中间角色或前作表现后才检查。认为一条高链不能直接成立时，具体定位缺桥，按[缺口补链](evidence-gap-recovery.md)继续找共同参照、直接承伤、制作方说明或其他独立锚；不能只写“特殊机制／合击／未证全力”就把整条表现从主档审查中删去。
- **属性与出力传递有依据。** 武器／护盾对抗一束攻击，先建立该载体与当次攻击的对抗能力，再主动检查持有者的驱动、身体受力、直接受击及可比交锋，判断哪些输出或体防可传；不自动复制，也不预先断言绝对不能传。区分参与的能力数量、当次齐射、是否全力、最大能力及实际作用比例；求生、杀意或惊讶可参与出力推断，不自动证明固定百分比，也不支持凭空判留手。器物专属抵消、偏转或克制须有依据，不能为压低高光临时发明；有可靠机制也不能当作普通动能硬抗。
- **受击状态、损伤与恢复分开。** 沿“受击前状态 → 实际承受 → 当次伤势／失能 → 治疗、装备供能或其他恢复 → 恢复后的行动”核对，不能把事后正常战斗倒写为当时无伤、自行恢复或未曾失能。严重受伤、濒死或后来获救也不抹掉此前确已承受的部分；分别判断耐受、承伤总量、热／辐射／机械抗性与恢复能力。虚弱时的有效表现须保留，向后期配置继承有据但不凭虚弱标签乘任意倍率。
- **能量来源的名称与实际载荷对应。** 恒星、黑洞、宇宙装置等来源或高温／高密度名称，不能自动替代当次投射功率、持续时间、照射比例、实际吸收与破坏终态；相关焦耳模型须有约束。可靠原文对全力、全量或整体作用的说明同样是有效证据，应核完整语境与适用物理／原生机制，不能因未提供科学参数便一律排除，也不能把供能、功率、源总储能和引力结合能悄悄互换。
- **灾难规模与解法贡献分开。** 分别核灾难将怎样发生、最终实际发生什么、角色以什么方式改变了它，以及是否有合击、环境能量、装置反馈或连锁放大。阻止一种大规模灾难，不自动等于输出了同等能量；打碎、汽化、抹除及结构崩溃也须按实际机制判断。合击总战果仍保留，继续查个人贡献与跨状态继承；不得无证平分或全部归给一人，也不得因存在合击而将该事件整项作废。
- **攻防与胜负不能靠未证子档制造。** 不把特能影响档无条件复制为肉身硬防，也不把血肉、宿体、人类外形或受伤直接当成低防依据。破解载体、断肢、耗尽、封印或放逐作为胜路时，仍须核接近、命中、破防、持续、反制与失能条件。未知上限不构成已证低上限；不能从任意填写的“甲国级、乙城级”推算压倒性差距，再为既定故事找解释。

**验收须区分证据、推理与工具。** 纯定性报告可以没有数值计算，也不以`anchors/edges/computations`的空或非空直接判质量；但需要的实际表现审查、特能审查和可复算模型仍按原协议调用。宿主接受的是关键来源语义、关系传递、选档与候选取舍，不能由模板批量填`complete/accepted`，不能先盖章再读。工具只校验其可处理的结构与计算，不会替宿主判断“这段原文足以支持这个档”。

能代表完整配置的合理主估允许有非关键不确定性。会改变主档、主要属性或决定性交互的缺桥仍未处理时，保持`partial/open`并继续补证；“这次只写故事”“另一条打法也能写”不能把材料缺口改为非关键。用户提出较高候选时按相同标准核查，不为纠正低估而倒填更高档，也不以严谨之名机械排除可靠设定和有据比较。

发现旧评级缺关键论证时，保留原作已成事实，撤回受影响的验收与依赖其成立的胜负置信，完成实质补查后再恢复；不得仅补更多字段或免责声明继续沿用旧优势方。更新遵从[复核与状态一致](rating-completion.md#重大改判与状态一致)。此要求只加强评级，不改故事的原作感、对白展开、入场设计、文学投入、媒体独立制作及故事版不强制新增读图的边界。

## 阶段一：把每个角色作为独立评级任务执行

只解析版本、时期、状态、装备、规则及作者明确改写的角色设定；评级统一使用 `mode:integrated`，依[综合选档](modes-scaling.md)纳入高光、通常、低谷和可靠设定，不再分三套评级。暂存指定胜者、情节、必用技能和结尾要求；它们在写作阶段恢复，不能倒推本阶段档位。角色具体人设与能力仍按独立评级所需研究，不能用剧情所需的几个招式替代完整能力档。

1. 将配置交给同一个单人研究入口。`rating-pipeline plan`支持单独评级的`rating_request`和故事的`writing_request`，二者编译到同一个研究任务；默认先交报告与来源，不先堆占位产物。有子代理时实际派发独立研究任务；无代理则逐角色使用同样输入开始搜证。任务不含新对手、预期胜者或剧情设计。已有合格档案也须实际打开当前状态、报告、来源与推导，判断配置、覆盖和规则是否匹配。
2. **宿主现在实际执行每个单人任务**，按[独立角色流程](character-rating-workflow.md)搜证、审表现、补链、计算、选档、完成九维并保存可单独交付的报告。有代理能力时可并行委派，每个任务独立处理；没有代理时逐个执行同样流程。任务文件生成、分派消息、检查器通过均不算研究已经完成。
3. 主动从所选阶段的主要攻击、防御、对手、装备及能力展开，审查直接战果与主要正反叠链。继承、合击、机制、出力和材料按既有规则判断；一条桥失败就定向寻找替代参照或模型，不能只找方便算的局部片段，也不为纠正低估自动采用未经支持的高链。
4. 宿主先实际阅读研究者交回的报告及关键原文，复演取档理由，判断更高候选与主要正反链是否真正得到处置；有实质缺口即补研究。研究者不代填主机接受，制作模板也不构成验收。
5. 内容充分后，把结论接入已有分析与归档。需要计算时，所需单人`analyze`只执行一次并保留实际输入与结果；CASE可含参照对象，但仅一个本次被评目标、没有`matchup`。纯定性报告按[轻量真实交接](rating-handoff.md)保存，不为交接制造空CASE。定性推理不编造J，不把重复保存文字当新证明。宿主只接受自己实际检查过的当前修订，后续未变原文和运算不重复处理。

故事关联评级按[故事取证边界](writing-rating-baseline.md#故事版取证边界)默认不新增读图、视频下载或逐帧测量，可复用真实已读且验收有效的画面结论。取消媒介步骤不减少主要战绩发现、来源阅读、关系推断、具体定档及九维研究。纯原创与作者完整给定的改编设定直接作为资料执行同样单人评定，无需虚构联网搜证。

## 阶段二：导入同一权威档案，再分析交互和写故事

按[真实档案交接](rating-handoff.md)导入已完成研究，普通PK、直接process及故事共同消费相同的已审定角色对象。纯定性研究可只用一份包含实际报告、评级、来源与宿主接受的dossier；需复算时引用已有CASE。旧八文件产物继续兼容，不把强制多写文件当作提高研究质量。

`independent_ratings`是评级权威，人物卡从它派生，旧`fighters[].ratings`不再独立决定档位。同一已选结论发生冲突时回到真实研究复核，不强行让候选、反例和其他状态等于主档。作者有据的局部改编只覆盖明确字段，原作接受记录保留。

只有各方独立评级均实际完成并验收，才加载[完整写作入口](writing-entry.md)、写作细则、原作感与优秀范例，分析胜路、关键交互、合理前因、过程与战后处置。作者指定胜者和过程在此恢复；它们约束创作，不反向改变原作档位。

发现漏掉的末期能力、重要表现或状态继承时，补实际研究并按受影响范围更新档案、接受和导入，再重评战局；未变证据/计算直接复用。不能只给故事加解释，或临时抬档、压档、添抗性保住情节。

## 最小命令契约

已有已完成并验收的独立产物时，优先一次运行导入与写作准备：

```text
python scripts/battle.py rating-pipeline --input assemble-and-prepare-request.json --output prepared.json
```

请求使用`operation:"assemble-and-prepare"`，其余字段与`assemble`相同。结果中的`writing_request`保留完整导入输入，`writing_preparation`是写作入口的实际检查结果；是否可继续由实际状态及缺项决定，不因调用组合入口就自动通过。它只合并已完成研究之后的本地步骤，不能用来跳过阶段一。CLI默认摘要，完整结果保存在输出文件；`--full-output`可显式恢复完整标准输出。

需要分步处理时继续使用原契约：

```text
python scripts/battle.py rating-pipeline --input plan-request.json --output plan-receipt.json
宿主实际执行单人任务，交真实报告与来源；需要模型时才运行相应计算，宿主实读验收
python scripts/battle.py rating-pipeline --input assemble-request.json --output assembled.json
将assembled中的writing_request保存为写作输入，再调用writing
```

`plan-request.json`使用`operation:"plan"`、`writing_request`和包外`output_dir`。`assemble-request.json`使用`operation:"assemble"`、同配置`writing_request`以及`artifacts:[{"character_id":"目标ID","dossier_file":"真实档案.json"}]`；已有八文件目录可继续用`artifact_dir`。禁止覆盖原作或旧报告；失效历史保留并标记，不自动迁移真实旧档为通过。

Python没有内置语义模型或Agent工具运行时，不能自行替任意宿主调用搜索或派生代理；**执行单人任务是读取Skill的宿主必须立即完成的工作**。流水线会生成可执行任务、导入并绑定真实产物，确定性工具无法证明原作已充分理解，不能把文件存在或重算一致称为语义正确。

## 验收看实际行为

同样版本、状态、规则与资料，单独问量级与用于故事前置时，主要候选链、主档与九维应一致；允许新增证据导致有记录的修订。故事结局、篇幅、人设节拍及对手变化不应反向改变独立档位。

真实试用必须先留下两份可读报告、主要链的采纳／排除理由和实际单人运行记录，再检查导入、交互和故事。还要验证只有旧评级JSON无法进入写作、产物变动会失效。测试检查执行顺序和研究结果，不以模板含有“先评级”、九个字符串非空或伪造的已完成标记判成功。
