## 保留用户九维，并增加 VSB 必要字段

| 用户维度 | VSB 对应及交付方式 |
|---|---|
| 输出 | Attack Potency（AP）；按招式、形态、装备分开。物理拳脚另列 Striking Strength；能量招式不自动叠给肉身打击。 |
| 体防 | Durability；分别写肉身、护盾/装甲与特殊抗性，不能以“最后活着”替代承受攻击强度。 |
| 智力 | Intelligence；至少使用一个现行标准名称并给领域、实绩、局限。IQ 数字与世界内部智力排行不能替代实绩。 |
| 战斗智商 | 单列战术判断，并在 Combat Skill 中说明具体决策、预测、临场学习、技巧与失败。VSB 没有用 Genius/Supergenius 等单词给 Combat Skill 统一分档；不编制该档表。 |
| 经验 | 单列训练、实战、对手类型与知识更新的实绩；年长/活得久不自动等于更强技巧，不杜撰 VSB 数字经验档。 |
| 特殊技能 | Powers and Abilities；发动、对象、机制、效果、距离、代价、对抗与抗性分别写，按具体能力原页核资格。 |
| 破坏 | Destructive Capacity/实际毁伤与 Environmental Destruction；说明单次、多次、连锁或环境效果。范围小不自动封顶 AP。 |
| 速度 | 分 Attack / Combat / Reaction / Travel / Flight；知觉时间另列。不能把远程光束速度、直线宇宙飞行或传送整体赋给反应与拳速。 |
| 体量 | 明确身高、质量、体积、形态与有效受击部位；需要 Large Size 等能力资格时另核对应规则。不能从体量直接推出 AP、Durability 或“总血量等于×焦耳”。 |

VSB 档案还应包含 **Tier/Keys、Lifting Strength、Striking Strength、Stamina、Range、Standard Equipment、Weaknesses**。用户要求的九维作为并行补充保留；没有根据的项写 Unknown/证据缺口，不能为了填满表格套“爆楼智力”。同一 Key 的版本、状态、配置须一致；不同 Key 不拼成一套综合数值。

### 智力、技巧与续航

Intelligence 现行标准名称：Mindless、Instinctive、Animalistic、High Animalistic、Below Average、Average、Above Average、Gifted、Genius、Extraordinary Genius、Supergenius、Nigh-Omniscient、Omniscient。允许不同领域不同等级。**慢动作知觉不等于计算能力；会用先进文明的设备不等于亲自发明。** Supergenius 的科技路线要求极广泛、至少 High 3-A 尺度的现实改写级发明等实绩；非科技路线也需理解/处理真实无限信息或相称实绩。全知须限定原作世界范围，不默认知道跨作品对手。[Intelligence](https://vsbattles.fandom.com/wiki/Intelligence?oldid=9703377)

Stamina 分持续出力、疼痛容忍、伤后行动三条。标准描述为 Unknown、Below Average、Average、Athletic、Peak Human、Superhuman、Infinite、Inapplicable，必须附实例。机械/亡灵/非实体不自动无限续航；无限能源不等于承受任意伤势；AP/体防相近也不自动共享续航。战斗时长要结合强度，不能只比小时数。[Stamina](https://vsbattles.fandom.com/wiki/Stamina?oldid=9439513)

### 耐久和拳脚叠链

先区分**无伤、没有痛苦反应、重伤存活、靠再生恢复**。电流、酸、纳米分解、内部震动、穴位、弱点与极小接触面积可能解释越防伤害；“伤到谁”必须连同“怎么伤到”审查。吐血、刺穿眼球、用细刃切到巨人体表不能直接把攻击者升为对方全身耐久。[Durability](https://vsbattles.fandom.com/wiki/Durability?oldid=9632884)

原页允许身体直接攻击且自身无痛/损伤时，用作用反作用支持相应身体耐久；**持武器攻击不自动套到持有者肉身**。强能量炮也不自动给拳脚相同 AP，需拳脚能伤到承受该炮的对象等桥接实绩。普通锋利/接触面积优势与真正 Durability Negation 分清。[Striking Strength](https://vsbattles.fandom.com/wiki/Striking_Strength?oldid=8752362)

### 射程不是输出，也不是整个人的统一范围

逐能力写有效到达/作用距离，并区别战斗、感知、预知和传送。现行近战范围是 Below Standard Melee 0–50 cm、Standard Melee 50 cm–1 m、Extended Melee 1–3 m、Several Meters 3–10 m；武器含手臂，但长柄武器不默认握最末端。高层射程要证明覆盖相应**整个结构**；能进一个异空间不等于 Universal+。预知一个人的未来，不等于看遍整条四维时空。[Range](https://vsbattles.fandom.com/wiki/Range?oldid=9709169)

## 常用限定词不能替代证据

按 [Attack Potency](https://vsbattles.fandom.com/wiki/Attack_Potency?oldid=9632883) 使用：

- **At least / At most**：已证下界/上界；不宣称精确峰值。
- **Likely / Possibly**：有根据且分别较有利/有限可能的判断，不能为无证据猜测贴词。
- **Higher / Lower**：同档更强/更弱的配置或招式；不能只靠形容词自动跨档。
- **Varies**：原作有明确机制导致变化；单纯前后矛盾不因此变成 Varies。
- **“+”**：数值高于该有限档上下界的算术平均值；工具在恰等中点时标出原文边界歧义。不能把汪吧“弱/标/强/超”机械翻译成 VSB 的 Low/High/+。

上述措辞应随所属属性、招式、Key 保留；不可看到一个可能上限就把全卡替换为已证上限。

## 物理与视觉核算：先判可用，再算数字

沿用证据包、视觉测量、单次表现因果审查与推导账本。每次写清原图/视频位置、比例尺与透视、材料/空隙率、破坏方式、时间、公式、SI 单位、中间值、估计区间及失败条件；工具成功不等于原作条件成立。VSB 的通用破坏系数是其社区简化约定，不冒充严格材料科学。[Calculations](https://vsbattles.fandom.com/wiki/Calculations?oldid=9632893)

实质规则：

1. **先确认材料与毁伤机制**：碎裂、粉碎、熔化、汽化、原子化不得互换；原子化/亚原子毁灭须明确证据。材质、温度、是否真正汽化及中空建筑的实体体积必须对应画面/文本。参数需要时查该页相应材质表及原始文献，不默认所有物体用岩石系数。
2. **举升不自动给 AP**：慢速持续举升与战斗爆发不同；只有快速爆发举升或可在战斗时限内使用的念动力等有适用理由时，才讨论其能量用于 AP。W 是功率，必须有时间或明确且展示的规则约定才能得到 J；N 不能直接变 J。
3. **KE 的 VSB 特别门槛**：FTL 不使用动能公式，也不把 FTL 速度夹到略低 c 人造高能。禁止由算出的 KE 反推人物速度/质量；跨场景计算输入还需过 Calc Stacking 审查。普通奔跑不自动对应 AP；实际弹体、攻击抛掷、巨物移动等按因果与一致性评估。
4. **相对论 KE 的社区上限**：除明确能量陈述等例外，使用 `min((γ−1)mc², 4×(½mv²))`，只适用于 `v<c`。这是 VSB 接受上限，不能把通用 physics 工具未经限制的相对论结果直接用作 VSB 主判。冲击实际停下却几乎未造成对应毁伤时，核实际损能与反证，不能只保留高 KE。
5. **全向运动不可把全部质量按最快外沿速度平移**：均匀密度、线性速度分布等前提成立时，二维扩张/散开分别用 `¼mv²`、`(1/12)mv²`；三维分别用 `(3/10)mv²`、`(1/20)mv²`，不是通用冲击万能公式。

动能规则出处：[Kinetic Energy Feats](https://vsbattles.fandom.com/wiki/Kinetic_Energy_Feats?oldid=9342768)。计算入门要求公开画面、输入和推导，不把未发布/未评审的新计算标成 VSB 已接受；搜索到的旧教程、参数或互相冲突的计算仍要核现行规则与认可状态。[Calculations Introduction and References](https://vsbattles.fandom.com/wiki/Calculations_Introduction_and_References?oldid=7978302)

### VSB计算入口与附加边界

```python
from vsb_physics import calculate

request = {
    "model": "relativistic_kinetic",
    "inputs": {"mass": 1, "speed": 296794533.42}
}
reviewed = calculate(request, sources=case["sources"])
# 先审画面/材料/归属；只有 status=="ok" 且 eligible_for_attachment==True，
# 才可使用 reviewed["result"]，再按VSB数值表定档。
```

`sources` 由外层 CASE 注入，不能在计算 request 内塞另一个来源目录自证。相对论模型默认执行 `min(K_rel, 4×K_Newtonian)`，区间各端点同样处理；任何端点 `v≥c` 都阻断，不能夹到略低 c，例外声明也不能使 FTL 动能公式有效。

如原作有独立明确能量陈述，可附以下**机制证据字段**请求例外；原文与确切位置必须能由 CASE 的可读 primary 来源核查，单纯社区计算、速度描写或自填“已认可”不行：

```json
{
  "vsb_policy": {
    "relativistic_exception": {
      "explicit_energy_statement": true,
      "statement": "这里填写原作实际给出的独立能量陈述及适用对象。",
      "source_ids": ["s-explicit-energy"]
    }
  }
}
```

该字段仅适用于 `relativistic_kinetic`。若例外不成立，输出 `undetermined`、无可附加顶层 `result`；不会悄悄把未证例外作为已证数值。

`mass_energy` 同样要求 `vsb_policy.mass_energy_conversion`：

```json
{
  "model": "mass_energy",
  "inputs": {"mass": 1, "conversion_fraction": 1},
  "vsb_policy": {
    "mass_energy_conversion": {
      "explicit_conversion_mechanism": true,
      "statement": "这里填写原作明确的物理质量—能量转换机制和实际转换份额。",
      "source_ids": ["s-conversion"]
    }
  }
}
```

材料凭空出现不能替代这个机制；旧 `applicability` 布尔值也不能绕过来源门槛，已知不是质能转换时保留 `blocked`。普通创造依下节社区创造标准／高层结构处理，不用 mc² 强行求 AP。

CASE 计算附加只选择政策处理后的顶层 `result`（完整 quantity），或 `result.value` 并明确相应单位；仍要通过单次表现和属性归属审查。`raw_calculation`、`mathematical_reference`、`policy_review`、`steps` 等是审计材料，**任何嵌套原始值都不可另选路径定级**。`status=blocked/undetermined` 或 `eligible_for_attachment=false` 时不附加，即使审计树里仍存一个很大的 J 值。数值门槛通过不等于已证明公式适用于该场景，也不等于 VSB 社区已接受。标准选择见 [VSB 模式](vsb-mode.md)，战斗持续条件与来源包见 [VSB 对战](vsb-combat.md)。

### 光束、时间与躲避

光束名为 laser、发光或来自科技设备不足以给 c。综合可靠的光/光子/确切光速说明、真实光源、反射/折射等证据，并检查弯曲、固体可触、速度变化和主要靠推撞等反证；硬光实体另需证据。即使光束已合格，也要排除预瞄闪避，确认角色开始移动时光束的位置；用同期位移比求角色速度，不能“躲光=必超光”。介质影响光速；有关资格尚未经过 VSB 人员讨论时，不能冒称已正式接受。[Laser/Light Beam Dodging Feats](https://vsbattles.fandom.com/wiki/Laser/Light_Beam_Dodging_Feats?oldid=9093267)

漫画慢动作/近身擦拳不要机械按一个未动像素或两格瞬间推出巨大倍率；动画需审剪辑、镜头切换和叙事时间。真实长度/时间未知时说明假设并给敏感性，不能把入门教程的示范时间当该角色原作事实。

### 凭空创造与质能转换

**只有原作明确这种机制时才采用 E=mc²**；凭空出现物体、变大、再生、能量生物实体化都不能凭“现实能量守恒”强制判成质量全转换。[Mass-energy conversion feats](https://vsbattles.fandom.com/wiki/Mass-energy_conversion_feats?oldid=9448480)

VSB 对真正创造另有**社区质量表**，不是 mc²；适用时核实为真实物质，排除幻象、移动既有物质与单纯进入现成空间。要传到常规攻击，须有共同能源/可调用出力的桥接与足够短时间；否则记创造/Environmental Destruction，而非自动给拳脚。小于月球质量的创造按该页表取对应档，天体和口袋现实按其专门规则；不从社区档位捏造一个精确创造焦耳值。[Creation Feats](https://vsbattles.fandom.com/wiki/Creation_Feats?oldid=8400132)

## 游戏 HP、伤害与规则性效果

HP、等级、伤害数字、重复小攻击磨死高耐久对象、开放地图几秒跨越和不可破坏场景，可能是游玩抽象；按原作设定、过场、稳定表现及反例核查。**不能把 HP 当焦耳，也不能只因是游戏画面而全部排除**：若游玩就是唯一主要描写，仍须分析其实际一致性与世界内支持。游戏机制表象与已经成立的原作能力分开，不用“Game Mechanics”标签随意取消不利表现。[Game Mechanics](https://vsbattles.fandom.com/wiki/Game_Mechanics?oldid=9666253)
